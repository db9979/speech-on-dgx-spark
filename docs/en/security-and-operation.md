# Security and operation

← [README](../../README.md)

## Security

- **Assistant without password**: off on new installs. Then only profiles (name and PIN) and devices with a key reach the assistant. Switch under *Settings → Security*.
- **Lockout after wrong attempts**: after 5 wrong passwords or PINs from one address (or 10 for one profile name or the admin password, from anywhere) the panel waits 1 minute, twice as long with every further lockout, at most an hour. On top, each name gets at most 30 wrong attempts a day. Addresses and browsers that logged in successfully before are not locked out by a stranger this way, also not on the road with a new address (cookie `speech_known`). The counts survive a restart of the panel and are pruned, so made-up names cannot grow them without end.
- **Reverse proxy**: behind a reverse proxy in the LAN (e.g. Synology) the real address from `X-Forwarded-For` counts, so one guesser cannot lock everybody out. Enter the proxy's address under *Settings → Security → Adressen des Reverse-Proxys* (reverse proxy addresses); the panel trusts that header only from there. Without an entry it counts only from a proxy on the Spark itself; proxies in the home network then share one address for the lockout (the panel log says "X-Forwarded-For … ignored").
- **Logins expire**: the admin login after 7 days without use, a profile login after 30 days (7–90 under *Settings → Security → Sign-in in the browser*, since V01.0.262); while in use they renew themselves. Logging out ends the login on the server too. *Me → Security → Log out everywhere* ends the profile's login in all other browsers. On https (also behind the proxy) the cookies are `Secure`.
- **Signed-in browsers** (since V01.0.262): *Me → Security* lists every browser the profile is signed in to (only a short name like "iPhone · Safari", first and last use, no address), with *Sign out* for each one; the admin sees the same list in the profile details. At most 20 per profile, the oldest ends first. Logins from before V01.0.262 appear after their next use.
- **Browser protection** (since V01.0.262): every panel answer forbids embedding in other pages (`X-Frame-Options`, `frame-ancestors`), guessing file types (`nosniff`), leaking addresses to other sites (`Referrer-Policy`) and microphone/camera for anything but the panel (`Permissions-Policy`); over https `Strict-Transport-Security` is added.
- **Strict Content-Security-Policy** (since V01.0.286): scripts only run as files from the panel (`script-src 'self'`): no script in the page, no `onclick="…"` handlers, no `eval`. So even injected HTML runs no code. Buttons in generated lists name their function with `data-on` (base.js `ON`); only what is registered there can be called. Pictures and sound also from `data:`/`blob:` (recordings, QR codes, the face), connections only to the panel itself, no foreign frames. Inline styles stay allowed (they run no code, older Safari versions in the iPhone app need them). The scanner in the self-test turns red on a new inline handler, inline `<script>`, `javascript:` link or `eval`; every browser test counts a CSP message as an error.
- **Undo** (since V01.0.286, plan "Bedienung gesamt" C5): *Zustand → Logs → Admin-Protokoll* shows the latest settings changes above the log (when, who, "Weather: off → on") with *Rückgängig* (undo). Kept are the last 50 saved changes from Einstellungen, Funktionen and the iPhone app's switches (`state/config-undo.json`, only names and short values). Never in it: secrets and addresses that need the admin code (keys, tokens, passwords, the language model address …), the *panel* section (ports, proxies: a wrong value could shut the admin out), lists and long texts. Undo only puts back values still as that change left them (ones changed again since stay and are named), with the same checks and service restarts as saving, and becomes an entry itself. The main admin sees all, a profile in its admin mode its own; managers none. Log: `config_undo`. Not in the backup (after a restore the old values no longer fit).
- **Security at a glance** (since V01.0.262): at the top of *Settings → Security* a traffic light of fixed checks (admin second step, age of the backup, short PINs, roles without second step, http instead of https, assistant without password, home network addresses, sign-in duration). Red points also show under *Status → Needs you*. Of PINs the panel only notes whether they are shorter than 6 characters, when set and at sign-in.
- **Second login step (authenticator app)**: for the admin under *Settings → Security*, for profiles under *Me → Security* once the admin allows it under *Features* (off on new installs; each profile decides for itself). Set up with a QR code; then the login asks for the six-digit code, plus 10 recovery codes for a lost phone. "Trust this browser" saves the code on your own device (since V01.0.286 see below); "Log out everywhere" (profile) or "Forget trusted browsers" (admin) ends that. While the admin has it on, HTTP Basic no longer works, and changing the password, restoring a backup, creating or moving device keys and changing PINs ask for a code every time. Devices with a key (speakers, Siri, Pebble, phone) need no code. Way back in: admin `sudo rm /var/lib/speech-spark/state/mfa-admin.json`; the admin resets a profile under *Profiles*.
- **Fewer codes** (since V01.0.289, plan `plaene/zweiter-schritt-seltener.md`): three things, kept apart by risk. **Trusted browsers**: whoever ticks "Trust this browser" at sign-in (the browser remembers the tick) enters no code there for the days under *Settings → Security → Vertraute Browser* (7 to 90, default 60); after 30 days without use it asks again. Every trusted browser is listed with a short name, since when, last use and "asks again from" (admin: *Settings → Security → second login step*, profile: *Me → Security*, the admin also in the profile details) and can be removed on its own; at most 10 per person, the one unused longest drops out. A new trusted browser sends a push note (admin: to the profile for admin notes or the main admin profile). Trust cookies from before V01.0.286 no longer count; enter a code once. **A confirmation counts 10 minutes**: after a right code, further important changes in the same login (admin login, the profile's browser login or the iPhone app's key) ask for no code for 10 minutes; a bar shows the time left with *End*. Memory only; signing out, *End admin mode*, *End* and a panel restart clear it. Always a fresh code: setting up, switching off and new recovery codes of the second step, the admin password, resetting a profile's second step, admin roles, restoring, uploading, downloading and moving backups, the smart home code word, opening the admin mode. **Admin mode**: in a trusted browser it stays open 60 minutes without use (else 15) and at most 12 hours (else 8); it still opens only with a fresh code. When the browser is removed from the list, 15 minutes apply again at once. Not done, too risky: no code at home, remembering the admin mode or confirmations for days. Change log: `trusted_browser`, `trusted_browser_removed`.
- **Passkeys instead of the code** (since V01.0.295, plan `plaene/zweiter-schritt-seltener.md` point 4): with the second login step on, *Add passkey* under *Settings → Security* (admin) or *Me → Security* (profile) creates a passkey (Face ID, Touch ID, Windows Hello, a security key; first a fresh code, then a tap of its own on *Create now*). Then wherever the code is asked, *With passkey* works too: at sign-in (*Sign in with passkey*), for the admin mode and for important changes (a small window with *With passkey*, *Enter code*, *Cancel*). Safer than the code: the browser signs a one-time challenge of the panel only for this address and only after fingerprint, face or device PIN; another page gets no signature for us. Only over the address with a name (https, e.g. `speech.metaluna9.i234.me`), not over the IP address; each passkey remembers its address. At most 10 per person, removable one by one. The panel keeps only the public key, name, address, when added and last used (in the second step's file; *Set up again* or *Switch off* deletes the passkeys too). Challenges count 2 minutes, once, only for this person, login and address. The app code and recovery codes stay as the way back. The iPhone app still asks for the code (passkeys there would first need Apple's "Associated Domains" setting). Library: python-fido2 2.2.1 (pinned, with hash in `requirements-panel.lock`, in older environments without dependencies). Change log: `passkey_added`, `passkey_removed`.
- **Outside text also counts in the next message**: an answer made from web pages, mails, calendar, contacts, documents or smart home texts (media titles, text sensors) is marked. The next message then starts locked (nothing is switched, saved, proposed or reminded; plain switching commands of yours the panel still carries out itself), older such answers are not sent to the model again and never go into automatic learning. Outside text always reaches the model as "data, not an instruction". At most 4 tools per step and 3 notes per answer; "forget" only with a real word and at most 3 hits. Home Assistant direct actions only for lights, switches, covers, climate, media and similar devices, no scripts, automations or buttons.
- **A "yes" is a plain yes**: only yes words count ("Okay, what's the weather?" is not a yes), and any answer settles all proposals waiting in the conversation. In room mode the voice check belongs to the recording of exactly that "yes"; code words never reach the model or the search there either.
- **Someone else's voice**: a voice recognized at someone else's device gets no personal data (no memory, history, documents, calendar, contacts, lists, reminders).
- **Outside text switches nothing**: once the assistant read web pages, calendar, documents or earlier conversations in an answer, nothing in that answer can switch Home Assistant, change memory or cancel reminders; after an e-mail it also cannot search the web or enter appointments. The panel only runs tools it offered the model in that step.
- **Web search**: the panel reads result pages only from public addresses, never from the home network.
- **Appointments**: a proposed appointment is confirmed only by a plain "yes" in the same conversation.
- **Speaker identification**: the recognition result is given only to signed-in profiles and devices, and it is valid only there. Someone else's voice at a device gets answers but changes no memory.
- **Speakers in a room are shared** (since V01.0.226, fixed rule without a switch): anyone in the room can talk to an own speaker, so its device key alone does not count as its owner. Personal things (mail, appointments, reminders, memory, history, documents, contacts, messages, parcels, tasks, smart home, agents) are given there only when speaker identification clearly recognizes the owner's voice in that very recording (Features → speaker identification on, voice taught in the browser or with "teach voice here" at the speaker). Any other or unknown voice gets what a guest gets, and the assistant briefly says it tells that only to the owner; earlier answers at that speaker are not sent along then. Without speaker identification or a taught voice nobody gets personal things at a speaker. Whose voice it was is set only by the panel itself (`esp32.py` → `chat_turn.shared_stranger`), never by a request. Each question kept from personal things this way shows under *State → Logs* in the speakers area as a yellow line "personal data withheld at <speaker> - <reason>" (reason: speaker identification off, no voice taught, voice not recognized, another profile's voice); a recognized owner voice as "owner's voice recognized". Since V01.0.235 numbers come with it: "match 0.68 of 0.75 needed" (similarity with the owner's voice and the value needed, strictness under Settings → speaker identification), "other profiles" (best similarity of another profile), seconds of speech without pauses and "taught here" (sentences taught at the speaker). With less than a second of speech the assistant asks to repeat the question as a whole sentence. "Teach voice here" takes five sentences and reports success only from three well understood ones. The lines name only the speaker and the reason, never the question, voiceprints or content; the speaker's diagnosis (Me → Speakers → Check) shows the same.
- **Code word at a speaker** (since V01.0.297, Features → Speaker recognition → Code word at a speaker and Me → Speakers, both off): three levels (`spkcode.py`). A clearly recognised owner voice as above. **Grey zone** (similarity at most 0.10 below the strictness, the owner still the best match) or an unusual moment (another profile less than 0.05 behind, under 1.5 s of speech, an unknown voice in this speaker's room mode in the last 2 minutes, a wrong code word lately): if the question asks for personal things (fixed word groups like mail, calendar, reminder, smart home or "mein/meine"), the speaker says "Sag bitte dein Codewort." and the question waits 60 s. Right: it is answered with the profile's data, follow-ups stay open for 2 minutes while the voice is at least in the grey zone. Wrong: "Das Codewort stimmt nicht.", nothing personal. After 3 wrong ones in 15 minutes this speaker stops asking for 30 minutes and the profile gets a notification. A **foreign voice** is never asked, so an overheard code word is of no use to it. The code word is an own one (not the smart home code word), at least 2 words and 8 letters, set only in the own browser with a fresh code, sealed in the vault, never sent back. The sentence with the code word goes to no model, history, protocol, diagnosis, board display ("[Codewort]") or journal; the journal only has "code word asked … (reason, numbers)", "right", "wrong (n of 3)", "locked". Waiting questions, failures and locks live in memory only.
- **No changes from foreign pages**: changing requests with a login cookie must come from the panel's own page (`Sec-Fetch-Site`/`Origin`). Scripts with a device key or HTTP Basic are not affected.
- **Secrets encrypted**: calendar and mail passwords and Home Assistant tokens are stored encrypted in the profile folders; the key is kept apart in `/var/lib/speech-spark/state/secret.key`.
- **Devices**: *Profiles* and *Me → Security* show when and from where each device key was last used; one click blocks it.
- **Change log**: *Status → Logs → Change log* lists logins, wrong attempts, lockouts and every change with time, address and who (`/var/lib/speech-spark/state/audit.log`).
- **Trace requests** (since V01.0.262, switch under *Settings → Operation → Logs*, off): *Status → Logs → Requests* lists every request to the assistant (time, profile, device, intent, a bead chain with one dot per step and the tool names, time to the first sound; red on errors, yellow from 5 s to the first sound) and shows the way of the chosen one: "Where the time went" (panel, language model, tools, speech output) on top, below a time line with arrival (device, length of the question), panel preparation (rights, allowed tools, lock after outside text), the switch (intent, tools x of y, required tool), every round of the language model (tokens read, tools offered, which one it calls), every tool (ok or not, characters, whether outside text), the answer check, the speech output (pieces, stalls) and the marks first word, first sound and done. Filters All/Errors/Slow, time range, search, "Related log lines" (journal lines from exactly that time) and "Copy for thread". Only fixed words and numbers are kept, never the question, the answer, tool arguments or results (a tool name the model makes up becomes "unbekannt"); at most 48 hours and 500 requests in `state/traces.jsonl`, not in backups. Per request the panel writes a journal line `anfrage: <id> | device | intent | tools | first sound | done | state` without a name (log area "Request"). The list shows a profile's name and device only when that profile allows it under *Me → Conversation → Privacy → "My name in the request log"* (only in its own browser login, never with a device key; also applies to older entries), otherwise "Profile"; guests and an unknown voice at a speaker show as "Gast". The main admin and co-admins can read it, not the Verwalter role.
- **Live page and live monitor** (since V01.0.312, switches under *Settings → Operation → Logs*, both off): *Status → Live* shows in one picture (design "1 Fluss") what the Spark does right now: devices with a running request on the left (group "Over the internet" for requests through the reverse proxy, sender shortened like 89.204.x.x), arrival, guard and the stages listening, switch, language model, tools, speaking in the middle, the targets by zone (on the Spark, home network, internet) on the right. Below: the way of the chosen request with times and "is here now", the guard's decisions with reason and check steps, the door (who came in from outside or was turned away), what the services give back (kind, size, time only), open channels, numbers and events. The last request stays as "last action" until a new one comes; then it fades in 10 seconds. Everything stays in memory (with "Trace requests" off nothing is written) and is gone after a restart; only fixed words, tool names and numbers, never question, answer, search terms or results; allowed pages from search results show as "Webseite", blocked addresses with address and port. Names only with the profile's consent ("My name in the request log"). The main admin and co-admins can read it, not the Verwalter role. **Live monitor in the home network** (sub switch): a screen opens `https://<Spark>:31443/live` and enters a 6-digit code once (*New monitor*, valid 10 minutes, once; wrong codes lock like a wrong login). It then keeps a key as a cookie (HttpOnly, SameSite=strict, only as a hash in `state/live-monitors.json`) that may only read `/api/live/state`; unused for 90 days → pair again, *Delete* ends it at once. Requests from the internet are refused (403). At most *At most at once* monitors (1–5, default 3); the monitor shows names only when *Names on the monitor* is on too, else "Person". Codes and pairings go to the admin log.
- **Only Qwen models**: as the model for speech recognition and voice the panel accepts only Qwen's own speech models (`Qwen/Qwen3-ASR-…`, `Qwen/Qwen3-TTS-…`); the engine loads models with their own code, so another repo could bring programs along.
- **Sensitive settings need a code**: changing the LLM address and key, the Telegram address, SearXNG, the speaker firmware source, models, the API key, "assistant without password" and reverse proxy addresses, downloading a backup and going back to the previous version ask for a code while the second step is on. The connection test sends the stored LLM key only to the stored address.
- **Backups without login keys**: the keys the panel signs logins with are not in backups; a restore keeps this Spark's own.
- **Device keys change nothing in the profile**: Siri, watch, speakers and own programs may talk to the assistant but not change connections (Home Assistant, calendar, mail, contacts, push), settings, devices or memory; that only works in the profile's own browser login, credentials and the code word also with a code. A new Home Assistant address needs the token again.
- **Spark as an MCP server** (since V01.0.303, all off, see [APIs and integration](apis-and-integration.md)): every program gets its own access per profile with its own tool list; the key is kept only as a hash. "Local" works only directly from the home network (nothing coming through the reverse proxy), "external" only with the second sign-in step, a fresh code and a warning. Questions through `ask_spark` count as outside text: read-only tools, no memory, no history. Acting is only a proposal the profile confirms in the panel with a code. Mail, memory, history, secrets and settings are never offered.
- **Room key for Home Assistant** (since V01.0.208, scope `room`): may only read where the profile's room mode listens (`GET /api/room/active`) and end it (`POST /api/room/end`), nothing else, and only while the admin has *Room mode for Home Assistant* on. Made only in the browser login with the code; a new one replaces the old. The iPhone app may use the same two paths only with the profile switch *Show room mode in the app*; starting and extending are never possible from there.
- **Event key for Home Assistant** (since V01.0.314, scope `haev`): may only `POST /api/ha/event` with an event name from the profile's list, nothing else, and only while the admin and the profile have *Home Assistant tells the Spark* on. The Spark says only the sentence set in the panel; whatever else Home Assistant sends is not read. Made only in the browser login with the code; a new one replaces the old. The instant notes go the other way, from the Spark to Home Assistant (WebSocket, to the checked address only, no redirects).
- **Back to the previous version**: from the panel the update only goes back to exactly the version that ran before, and never to before the security fixes of V01.0.75.
- **Size limits before reading**: the panel and the speech services refuse requests that are too large, and uploads without a login, before reading them. WAV files with a nonsense sample rate, very long recordings, Word files that unpack to huge sizes and calendars repeating every second or minute are refused or capped; calendars are expanded outside the panel's main loop.
- **Memory limit**: the panel and the speech proxies have a fixed memory limit (`MemoryMax`) and their own `/tmp`; a runaway restarts only that service and takes nothing from the LLM lanes.
- **Load limits**: per profile or address at most 30 (guests) or 120 chat requests and 60 or 240 transcriptions a minute; guests share at most 4 running answers and 3 transcriptions, the watch at most 8 running answers. Text to speech takes at most 20,000 characters per request. Audio is capped to sensible lengths when converted (voice message 10 minutes, voice sample 2 minutes, transcription 2 hours).
- **Outbound connections**: profile calendars, address books, task lists and mailboxes may only be on internet addresses; servers in the home network (e.g. a NAS) only once the admin ticks *Settings → Security → Heimnetz-Adressen erlauben* (allow home network addresses). Home Assistant may always be in the home network. The Spark's own services (ports 30000 to 31099) and addresses like 169.254.x are never reachable. The panel connects to exactly the checked address (also for web pages from search), checks every redirect again, cuts answers at 20 MB (also packed ones) and sends credentials only to the site they were entered for, never unencrypted.
- **Speech services**: the API key may only be empty while speech recognition and speech output listen on 127.0.0.1 only. Other web pages may use the services from a browser only while a key is set. A reference recording for cloning is only taken inline (`data:audio/…`, at most 15 MB), never as an address.
- **Update as root**: install and update write into the service user's folders only as that user or by renaming a file made in `/etc` (never follows a link); root reads the qwen38 key only from a real file without links that belongs to the home folder's owner. Password and API key are no longer in the update log (`sudo speech-spark key`, password in `/etc/speech-spark/panel.env`). An update whose history was rewritten on GitHub is not taken. From V01.0.157 the panel and `update.sh` install only versions whose "Tests" run on GitHub passed; if GitHub cannot be reached, nothing changes. Newer changes that are untested or red only show up as a note in the panel. `sudo update.sh --newest` takes the newest one by hand anyway. If you sign your versions, put the allowed keys into `/etc/speech-spark-signers` (format of `ssh-keygen` "allowed signers", owned by root); then the update only takes signed versions. The panel's Python gets packages only from PyPI.
- **Mailbox tidying**: Message-IDs are used only when they look like one, and compared exactly after a search. Only mail whose sender address matches exactly is moved, and nothing when the mail server has renumbered the inbox since the proposal (UIDVALIDITY).
- **Admin logout**: logging out also ends all older and renewed copies of that login. *Settings → Security → Admin überall abmelden* (log the admin out everywhere) ends the admin login in every browser. Wrong passwords over HTTP Basic also count against the admin password itself; new passwords need at least 10 characters.
- **Main admin as a profile** (since V01.0.275, plan "Vereinheitlichen" phase 7): under *Users as admins* the panel password can give exactly one profile the role **main admin** (only with the password, never from an admin mode). That profile signs in once (PIN and second step) and opens the admin mode with its code; then it may do everything the panel password can (roles, change log, restoring and downloading backups, changing admin profiles, only not its own through the admin pages). The password itself, its second step and *sign out everywhere* stay with the password: it is the emergency access when no profile works. Only the password gives and takes the main admin role.
- **Users as admins** (since V01.0.255, switch under *Settings → Security*, off; only with the main admin's second login step): the main admin (panel password) gives up to 5 profiles a role. A **co-admin** may do everything the main admin can except: change roles and the switch, the admin password and the admin's second step, the admin's *sign out everywhere*, restore, download, delete or make move backups, read the *change log*, and change the PIN, second step or devices of a profile with an admin role, or delete it (its own too). A **manager** reaches only Status (monitoring, logs), People and devices and the function switches. A role alone gives nothing: the profile needs its own second login step and opens the **admin mode** under *Me → Security* with a fresh code (like sudo). It ends after 15 minutes without use (a page that only reloads the status does not count) and after 8 hours at the latest, when the profile signs out, with *End admin mode*, and at once when the main admin changes or takes away the role, switches the switch off or one of the two second steps goes off, or when the profile's PIN or *sign out everywhere* changes. In the browser it holds only together with the same profile's login, from the iPhone app only while that app key exists and *Manage the Spark in the app* is on. Important changes ask for the profile's code. Every admin action is listed with its name under *Status → Logs → Admin log* (the main admin sees all, a profile only its own); optionally a chosen profile gets a notification when someone opens the admin mode. The role never works through speech, speakers, the watch, Telegram, mail or Siri, and guests never get one. Roles go into the backup (`state/admins.json`), the key for the admin mode does not.
- **Small things**: the bot deletes a Telegram message containing the Home Assistant code word (or asks you to, if Telegram refuses). Parcel mails whose sender your own mail server reports as forged (DMARC, SPF and DKIM) do not count. Guests only see the kind of an error, no internal addresses. The speech services' `/health` and `/v1/voices` show details only to the Spark itself or with the API key. Only known form fields go on to speech recognition. Names in the page's buttons are escaped for JavaScript.
- **Passwords are never spoken** (since V01.0.222, fixed rule without a switch): both speech services replace passwords, code words, PINs, TANs, one-time and confirmation codes, keys and tokens with "nur schriftlich sichtbar" ("shown in writing only" in English) before any output (`textnorm.hide_secrets`), whatever the text clean-up switch says. A value is recognised after "password … is/:", as a number right after "PIN", "code" or "TAN", and as a long key of letters and digits; "the password is wrong" stays. This covers the browser, speakers, Telegram voice messages, Wyoming and reminders; Siri gets its answer without the values too. The written text (chat, app history, Telegram text) keeps the values, since that is where you read them and only where you are signed in.

- **New people by invitation** (since V01.0.276, *Personen und Geräte → Neue Personen*, off): invitation only, there is no open sign-up. The admin creates an invitation (suggested name, starter pack, valid 1, 7 or 30 days) and gets a link, a QR code and a card to print; the link needs the panel's https address. Every link works once, the Spark keeps only its fingerprint (SHA-256), at most 50 are open, used ones disappear 7 days after acceptance or at once with the deleted profile (its PIN links too), expired ones after 30 days. Wrong codes count towards the lockout; whether a name is taken is only told to someone with a valid code. The PIN needs at least 6 characters. **Starter packs** ("Familie", "Gast plus", editable) only switch on profile switches of functions the admin has on, never areas of "Spark verwalten". **Second step**: by default "required for e-mail, documents, jobs"; a profile from an invitation gets these three only after setting up the second sign-in step and cannot switch it off itself afterwards (fixed check in the panel, reason "mfa" under Me and Wer darf was). The main admin gets a push message for every new person. The profile details have **PIN link** (a new PIN by link instead of passing a PIN on; with the second step only with a code) and **Remind** (push to the person, at most once per hour). Audit log: `invite_made`, `invite_used`, `invite_pin`, `invite_app`, `handoff_login`.
- **"Los geht's"** (since V01.0.276): after the invitation, *Me → Los geht's* walks in five steps (welcome, secure, devices, services, done) through everything the profile may use, with direct links to the pages under Me and QR codes for the iPhone app and pairing. The Spark ticks off what is done itself (second step set up, iPhone paired, calendar there …); the browser can only set "later". The admin sees "Einrichten x von y" in the profile list.
- **Continue on the phone** (since V01.0.276, switch under *Neue Personen*): on the computer "Los geht's" shows a QR code (2 minutes, once). The phone then shows a number; on the computer you tap the right one of three numbers, only then is the phone signed in to the same profile. A wrong number ends the attempt. Device keys cannot start a handoff.
## Kill switch (Notaus)

The red "Notaus" button (bottom of the sidebar, on phones at the top of Manage) stops the Spark in three stages. Triggering needs no code and only goes up; lifting is for admins only.

| Stage | Name | What stops |
|---|---|---|
| 1 | Outside closed | Everything over the internet or the reverse proxy (also MCP from outside), Telegram; the Spark itself reaches nothing on the internet (netguard, web search, weather, transit, Wikipedia, parcels, reMarkable, firmware and app downloads). The home network goes on. |
| 2 | Hands off | Plus every action: smart home, mail drafts and tidying, messages and announcements, appointments, lists, new reminders, reMarkable, MCP actions, memory. No "yes" carries anything out, waiting proposals are dropped. Running jobs are held, new ones refused; "on its own", Home Assistant notes (and their live connection), briefings, mail tidying and learning pause. The assistant still answers from what it knows and may read. |
| 3 | All quiet | Plus no conversation, no speech recognition; speakers, Wyoming, room mode and reminders are silent. The panel shows only the Notaus page; login, status, logs and lifting work. |

- **Who triggers:** every admin (also co-admin and manager); every signed-in profile when Settings → Security → "Notaus also for profiles" is on (off by default), also from the iPhone app and on the way. Never guests, speaker, Siri or watch keys, Telegram, MCP or the language model.
- **Lifting:** only the main admin or a profile in its admin mode (owner, co-admin), only in a browser (no app key, no HTTP Basic), only in the home network, with a fresh code (without a second step: the panel password again). Choice: back to stage 1 or off; held jobs then run on or are cancelled (default).
- **Home network** means a direct connection from a private network. Through a reverse proxy only what a listed proxy (Settings → Security → Reverse proxy) passes on as a home address counts; a listed proxy without that counts as outside. So list the proxy there.
- **Kept** across restart and update (`state/notaus.json`). A damaged file counts as stage 3, never as off. Way out without the panel: `sudo rm /var/lib/speech-spark/state/notaus.json`.
- **Visible:** red band on every page, a card under Status (kinds and counts since it was triggered, never contents), a push to the admin profiles when triggered and lifted, an entry in the admin log. Status → Live and the live monitor /live show a red band with stage, time, channel and per kind "held" with a count (never the reason or a name) and keep running in stage 3 (reading only; pairing a new monitor waits).
- **Not yet:** triggering by Telegram, voice, Home Assistant, ESP32 button, Pebble and guard rules (coming).

## Stability

- **Backups**: every day, before every update, before going back to the previous version and before every restore the panel backs up profiles (memory, conversations, documents, calendars, mail accounts, smart home, speaker ID), cloned voices, settings, the panel password and the shared state of the Spark (the admin's second login step, iPhone push key and devices, Telegram bot, browser push key, ESP32 speakers, agent services, own test questions) to `/var/lib/speech-spark/backups`. Counted separately, the newest seven daily or manual ones and the newest five from before an update, rollback or restore are kept. *Settings → Update and backup → Backup* downloads, restores or deletes each one and restores a downloaded file. A restore checks the settings like the settings page does, caps the size and swaps all parts or none; the current state is backed up first. Passwords and tokens are in the backup encrypted, the key is not: on another Spark they have to be entered again. An admin second login step the Spark cannot read is then not taken over (the current one stays). For a move there is the **move backup**: it also carries the key, encrypted with a password you type (at least 12 characters, scrypt + Fernet). It restores only with the same password; a wrong one changes nothing, and after five wrong ones in an hour the panel waits. The Spark's login keys are in no backup, so after a move everyone signs in again. Whoever has the file and the password can read all stored credentials: keep them apart.
- **Backup to the outside** (since V01.0.286, plan "Bedienung gesamt" D4, off): *Settings → Update und Sicherung → Sicherung nach außen* (main admin only, changes with the admin code). Once a day a move backup goes over WebDAV into a folder (NAS, Nextcloud, Synology; https only, through netguard, home network allowed), first encrypted as a whole with the backup password (scrypt as for the move backup, AES-256-GCM in 1 MiB pieces, each numbered and the last one marked: cutting, swapping or changing shows when decrypting). The NAS only sees encrypted data. Restore: download the file (`…-offsite.tar.gz.enc`) from the NAS and load it under *Aus Datei wiederherstellen* with the backup password, also on a new Spark; wrong passwords count as for the move backup (5 per hour). Without the password the copy is lost: write it down. WebDAV password and backup password are sealed in the vault (`state/offsite.json`, part of the backup), never in a log; a new address needs the WebDAV password again. The last 7 copies stay there; only what this Spark sent itself is deleted. Runs like the daily backup only in speech pauses (`vorrang.py`), after a failure the next try after 6 hours; *Jetzt senden* right away. Logs: `offsite_backup`, `offsite_failed`.
- **Fixed package versions** (since V01.0.286): the panel's Python environment (`venv-panel`) is built on a new install from `app/requirements-panel.lock`: every version fixed and every file checked against its hash (`pip --no-deps --require-hashes`: the file already holds every dependency; `packaging` stays at version 24 or later although rmscene asks for an older one, see `requirements-panel.override`); the GitHub test installs the same file, so exactly what gets installed is tested. An environment that already exists (like on tars) keeps its packages until it is built again (`sudo rm -rf /opt/speech-spark/venv-panel` and `install.sh`; after that it stays with the lock file). To change the list: `app/requirements-panel.in` and `install.sh`, then `uv pip compile --universal --generate-hashes --python-version 3.11 --override requirements-panel.override requirements-panel.in -o requirements-panel.lock`; `tests/test_lock.py` checks both lists match and every line has hashes.
- **Back to the previous version**: after an update the update card shows "Back to the previous version", which installs the version that ran before (only versions of the official branch). By hand: `sudo /opt/speech-spark/src/update.sh --to <commit>`.
- **Watchdog** (*Settings → Operation*, on by default): restarts ASR, TTS or an engine that does not answer for 5 minutes, works for 5 minutes without finishing a request, or loads for 45 minutes; at most three times an hour. Every restart is shown on top of the admin pages and in the change log.
- **Live check**: after every update (and on request) the language model answers once and has to call a tool (tool choice), web search has to find something (when switched on), speech output says a sentence and speech recognition has to understand it again. A failure is shown on top of the admin pages.
- **Answer time**: for every answer the panel keeps for two weeks how long it took until the first sound (only time, seconds and kind of device, `latency.json`). *Status → Checks → Funktionsprüfung* shows the median of the last 24 hours and of the days before. When it got clearly slower (at least 10 answers, median above 1.5 times and 1.5 s more) a note shows on top of the admin pages.
- **Where the time goes** (since V01.0.218): with the detailed diagnosis "Gespräch" (Logs → Advanced) the panel writes `chat: detail zeit: …` lines after each answer: panel preparation, per model round the tokens read (and how many came from the cache, if the server reports it), first word, thinking text in characters, duration of the round and of each tool, first sound. Counted from the moment the question arrives; speech recognition before that shows in the timings below the chat (Me → Conversation → Show timings). Numbers and tool names only.
- **Faster answer start** (`chat.prompt_cache`, Settings → Assistant → Language model, off): the minute-exact time no longer sits early in the system prompt but goes as a "note from the panel" at the end of the question (only in the call to the model, never in history or log). Instructions, tool list and earlier history then stay the same from turn to turn, and a server with prefix caching (vLLM default) only has to read what is new.
  - Since V01.0.304, with the switch on, the whole start stays the same: the model always sees the same tool list (everything the profile's rights allow). What holds for this question only goes into the same note at the end of the question: fewer tools from targeted tool choice ("Für diese Frage stehen nur diese Werkzeuge bereit …"), locks after mail or outside text, results of a "yes", role, room, document and extension hints. Only the tools the rules leave are run; the panel refuses any other (`chat_tools.run`). Rounds without tools send the list with `tool_choice: none`. The history starts at an "anchor" question (checksum of its text) that stays first for several turns while the browser's window moves on; at least half of the history stays.
- **Fetch clear questions directly** (`chat.direct_read` plus the profile switch `direct_read`, both off, never guests, V01.0.304): short, plain reading questions are fetched by the panel itself, by fixed whole-sentence rules (`intent.DIRECT`): "Habe ich neue Mails?" → `mail_list`, "Welche Erinnerungen habe ich?" → `reminder_list`, "Wie ist das Wetter?" → `weather` (today, home place), "Wo ist mein Paket?" → `parcels`. Only tools the turn offers anyway and that are not locked, without arguments. The result goes to the model like any tool result (mail as outside text); the first round is saved. Logs → Requests shows the step "… (Panel)".
- **Fetch ahead on a question back** (`chat.prefetch` as a sub-switch of Targeted tool choice plus the profile switch `prefetch`, both off, never guests, never an unrecognised voice at a shared speaker, V01.0.307; `vorab.py`): when an answer ends with a question back (last sentence with "?"), the panel at once fetches in the background what the next answer will most likely read, while the question is still spoken: the calendar from today to 8 days ahead, the newest mails (like `mail_list` without details), the weather at home, the parcels. Fixed rules decide which: the router's groups on the person's own words, on the question back only when nothing from outside was read in this answer. Reading only, only for tools this turn offered the profile and that did not run in this answer yet, at most 3, each at most 5 s, one per profile and 4 on the whole Spark at once. The data only lands in the caches calendar, mail, weather and parcels keep anyway (same duration as after a normal fetch); nothing is said, shown or stored, and the model only sees it when it calls the tool itself in the next answer, with that answer's rights and locks. Since then a calendar request for a shorter period takes a longer one from the cache. It does not wait behind "voice priority": these are network requests only and would otherwise come after the speaking. Journal (area conversation): `vorab: geholt …` with duration and `vorab: genutzt …` when the next answer reads from it within 90 s; Logs → Requests and Status → Live show one step "… (Panel)" per service (e.g. `calendar_events (Panel)`).
- **Model routing beside the preparation** (V01.0.307): with "questions no rule recognizes" set to "the language model sorts them", that call now starts right after the router and runs beside the panel's other preparation. Without fast answer start the turn waits for it as before (at most 4 s); with fast answer start the model sees all tools anyway, so it waits at most 0.3 s longer and leaves a later pick out (line `weiche: Modell-Zuordnung …`; since V01.0.312 also at the step "Weiche" under Logs → Requests: gewählt, zu spät or keine).
- **Breakdown per round** (Logs → Requests, V01.0.304): each language model round shows the characters of instructions, tool list and conversation and, if the server reports it, how many tokens came from the cache. Numbers only.
- **Language model gone**: when the language model cannot be reached or does not answer, the assistant says so in a fixed sentence, also on speakers, the watch and the iPhone.
- **Quality test**: after every update (when the live check passed) and on request (*Status → Checks → Qualitätstest → Jetzt prüfen*) the panel asks the real language model 20 fixed questions, most also in two other wordings, with prepared tool results (appointments, mail, reminders, search, memory) and checks that it picks the right tool and what is heard after the answer check. A failure runs once more (then "only on the second try"); the history of the last 20 runs (`quality-history.json`) marks questions as "newly broken" or "wobbles". Newly broken questions show as a note on top of every admin page for a week. No real data is read or changed. While the test runs, a bar shows which question it is on and roughly how long it still takes. Afterwards only questions with a finding stay open (failed, only on the second try, answer check held something back), one line each with the reason; the answer opens on tap. All other questions are folded below.
- **Memory warning**: when free memory drops below *Settings → Operation → Warn below* (default 10 GiB), every admin page shows a warning on top; DGX OS kills processes at about 8 GiB.

## Self-test

Every install and update runs the panel's self-test (`app/tests`) against fake LLM, TTS and Home Assistant servers in a throw-away directory: login and access, that profiles never see each other's memory, documents, conversations, mailboxes or Home Assistant, the chat tools, learning from conversations, calendar and text cleaning. It runs before the new version goes live. In an update a failure stops the update and the old version keeps running; on a first install it is only reported. The result is in the update log. It includes the security checks (`test_hardening.py`, one test per guard) and a scanner (`test_scanner.py`) that refuses new code using `shell=True`, `eval` or the like, a route without a login, an upload read without a size limit, values in `onclick` not escaped for JavaScript, or an assistant tool not sorted as "reads outside text / changes something / own data only". By hand: `cd /opt/speech-spark/app && sudo /opt/speech-spark/venv-panel/bin/python -m unittest discover -s tests -t .`

## Logs

All speech services log into their own journal (`journalctl --namespace=speech-spark -u 'speech-spark-*'`), capped at 500 MB and 14 days; journald deletes older entries automatically. Adjustable under Settings → Operation, effective after the next update. The panel's constant status polls are not logged at all.

**Diagnostic filters in the panel** (since V01.0.141): *Status → Logs → Diagnostic filters* replaces `journalctl … | grep -E "room:|esp32:" | tail -30` on the console. Tick `chat:`, web search (`chat: web search`), `homeassistant:`, `room:`, `esp32:`, update and self-test (unit `speech-spark-update`) and errors (error, Fehler, traceback, failed, warn); several ticks mean "or", none shows every line. Time range 10 min to 24 h, 30 to 1000 lines (newest kept); "Copy" takes the output including a header with filter and hit count. Admin only, at most 60 requests per minute. Filtering runs in Python against a fixed list; only numbers from fixed lists reach `journalctl`. Bot tokens, bearer keys, `password=`/`token=`/`key=` values and logins inside URLs are blacked out before display.

**Logs page "overview first"** (since V01.0.212): tabs Diagnosis, Services, Update and Changes. Under Diagnosis tiles show the error count and the three busiest areas with a small history over the time range (tap to filter), below the newest error with a fixed hint (e.g. HTTP 401 from Home Assistant → token expired). Filter buttons with counts: conversation, web search, router, Home Assistant, room, speakers, Telegram, mail and "errors only". Each line shows time, area and message; errors red, warnings yellow (fixed word list in the panel), repeated lines as "×n", pauses from 2 min as a divider. Search runs in the browser over the loaded lines only. "Live" reloads every 10 s (services every 3 s) and pauses while you scroll up or select text. "Copy for thread" takes version, filter and the raw lines in a code block.

**Telegram: one poller only** (since V01.0.214): Telegram hands new messages to one `getUpdates` at a time. Up to V01.0.213 the panel's startup tasks ran twice (the https server ran them again), and the two Telegram pollers kicked each other out every 15 s ("Conflict: terminated by other getUpdates request"). Now the https server starts without its own startup tasks, and a second poller in the same process is not started. If Telegram still reports a conflict, another program uses the same bot token: the Spark then waits 5 s, 30 s, 1, 2, 5 and at most 10 min, logs only the second and every 20th time (without the token) and shows a hint under State and Integrate → Telegram to use the token in one place only or get a new one from @BotFather. A single conflict right after a restart is normal (the old poll runs for up to 25 s).

**Weather service briefly down** (since V01.0.214): when Open-Meteo answers the weather note with 5xx or 429 or not at all, the log shows a warning ("retry in 10 min") instead of an error, and the Spark tries again every 10 min within the time window.

**Web requests in the logs** (since V01.0.215): for web server lines ("GET /api/… 200 OK") only the status code makes a line red (500 and up), never words in the address. The panel no longer writes the log page's own requests to the journal at all. Update lines quoting a version text ("Available: 46fb0e8 …", "Update finished: …") get no colour (since V01.0.216). The time may read "+0200", "+02:00" or "Z" (since V01.0.217; before, "+02:00" left every area at 0).

**Detailed diagnosis per area** (Logs → Advanced): room mode, speakers, Home Assistant and conversation can be switched on for 15 min, 1 h or 4 h; afterwards and on every restart they are off again. They add `… detail …` lines with numbers and decisions only (recognition time, answer time, word count, duration of a Home Assistant call, history size, offered tools), never heard or written text, names or secrets; redaction still runs. Admin only, rate limited.
