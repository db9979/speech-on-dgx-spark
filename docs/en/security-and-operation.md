# Security and operation

← [README](../../README.md)

## Security

- **Assistant without password**: off on new installs. Then only profiles (name and PIN) and devices with a key reach the assistant. Switch under *Settings → Security*.
- **Lockout after wrong attempts**: after 5 wrong passwords or PINs from one address (or 10 for one profile name or the admin password, from anywhere) the panel waits 1 minute, twice as long with every further lockout, at most an hour. On top, each name gets at most 30 wrong attempts a day. A browser that logged in successfully with that name before is not locked out by a stranger this way, also not on the road with a new address (cookie `speech_known`). Since V01.0.402 only the browser counts, not the address and not a login with another profile: a housemate with a profile of their own cannot guess another profile's PIN without the lock. The counts survive a restart of the panel and are pruned, so made-up names cannot grow them without end.
- **Reverse proxy**: behind a reverse proxy in the LAN (e.g. Synology) the real address from `X-Forwarded-For` counts, so one guesser cannot lock everybody out. Enter the proxy's address under *Settings → Security → Adressen des Reverse-Proxys* (reverse proxy addresses); the panel trusts that header only from there. Without an entry it counts only from a proxy on the Spark itself; proxies in the home network then share one address for the lockout (the panel log says "X-Forwarded-For … ignored").
- **Logins expire**: the admin login after 7 days without use, a profile login after 30 days (7–90 under *Settings → Security → Sign-in in the browser*, since V01.0.262); while in use they renew themselves. Logging out ends the login on the server too. *Me → Security → Log out everywhere* ends the profile's login in all other browsers. On https (also behind the proxy) the cookies are `Secure`.
- **Signed-in browsers** (since V01.0.262): *Me → Security* lists every browser the profile is signed in to (only a short name like "iPhone · Safari", first and last use, no address), with *Sign out* for each one; the admin sees the same list in the profile details. At most 20 per profile, the oldest ends first. Logins from before V01.0.262 appear after their next use.
- **Browser protection** (since V01.0.262): every panel answer forbids embedding in other pages (`X-Frame-Options`, `frame-ancestors`), guessing file types (`nosniff`), leaking addresses to other sites (`Referrer-Policy`) and microphone/camera for anything but the panel (`Permissions-Policy`); over https `Strict-Transport-Security` is added.
- **Strict Content-Security-Policy** (since V01.0.286): scripts only run as files from the panel (`script-src 'self'`): no script in the page, no `onclick="…"` handlers, no `eval`. So even injected HTML runs no code. Buttons in generated lists name their function with `data-on` (base.js `ON`); only what is registered there can be called. Pictures and sound also from `data:`/`blob:` (recordings, QR codes, the face), connections only to the panel itself, no foreign frames. Inline styles stay allowed (they run no code, older Safari versions in the iPhone app need them). The scanner in the self-test turns red on a new inline handler, inline `<script>`, `javascript:` link or `eval`; every browser test counts a CSP message as an error.
- **Undo** (since V01.0.286, plan "Bedienung gesamt" C5): *Status → Logs → Admin log* shows the latest settings changes above the log (when, who, "Weather: off → on") with *Rückgängig* (undo). Kept are the last 50 saved changes from Settings, Features and the iPhone app's switches (`state/config-undo.json`, only names and short values). Never in it: secrets and addresses that need the admin code (keys, tokens, passwords, the language model address …), the *panel* section (ports, proxies: a wrong value could shut the admin out), lists and long texts. Undo only puts back values still as that change left them (ones changed again since stay and are named), with the same checks and service restarts as saving, and becomes an entry itself. The panel password and admins see all; managers none. Log: `config_undo`. Not in the backup (after a restore the old values no longer fit).
- **Security at a glance** (since V01.0.262): at the top of *Settings → Security* a traffic light of fixed checks (admin second step, age of the backup, short PINs, roles without second step, http instead of https, assistant without password, home network addresses, sign-in duration). Red points also show under *Status → Needs you*. Of PINs the panel only notes whether they are shorter than 6 characters, when set and at sign-in.
- **Second login step (authenticator app)**: for the admin under *Settings → Security*, for profiles under *Me → Security* once the admin allows it under *Features* (off on new installs; each profile decides for itself). Set up with a QR code; then the login asks for the six-digit code, plus 10 recovery codes for a lost phone. "Trust this browser" saves the code on your own device (since V01.0.286 see below); "Log out everywhere" (profile) or "Forget trusted browsers" (admin) ends that. While the admin has it on, HTTP Basic no longer works, and changing the password, restoring a backup, creating or moving device keys and changing PINs ask for a code every time. Devices with a key (speakers, Siri, Pebble, phone) need no code. Way back in: admin `sudo rm /var/lib/speech-spark/state/mfa-admin.json`; the admin resets a profile under *People and devices*.
- **Fewer codes** (since V01.0.289, plan `plaene/zweiter-schritt-seltener.md`): three things, kept apart by risk. **Trusted browsers**: whoever ticks "Trust this browser" at sign-in (the browser remembers the tick) enters no code there for the days under *Settings → Security → Vertraute Browser* (7 to 90, default 60); after 30 days without use it asks again. Every trusted browser is listed with a short name, since when, last use and "asks again from" (admin: *Settings → Security → second login step*, profile: *Me → Security*, the admin also in the profile details) and can be removed on its own; at most 10 per person, the one unused longest drops out. A new trusted browser sends a push note (emergency access: to all admins). Trust cookies from before V01.0.286 no longer count; enter a code once. **A confirmation counts 10 minutes**: after a right code, further important changes in the same login (admin login, the profile's browser login or the iPhone app's key) ask for no code for 10 minutes; a bar shows the time left with *End*. Admins (panel password or a profile with a role, signed in with the second step) are not asked at this level at all (since V01.0.541). Memory only; signing out, *End* and a panel restart clear it. Always a fresh code: setting up, switching off and new recovery codes of the second step, the admin password, resetting a profile's second step, admin roles and the main admin, restoring, uploading, downloading and moving backups, the smart home code word. The former admin mode is gone since V01.0.541: admin rights follow the profile's sign-in. Not done, too risky: no code at home, remembering confirmations for days. Change log: `trusted_browser`, `trusted_browser_removed`.
- **Passkeys instead of the code** (since V01.0.295, plan `plaene/zweiter-schritt-seltener.md` point 4): with the second login step on, *Add passkey* under *Settings → Security* (admin) or *Me → Security* (profile) creates a passkey (Face ID, Touch ID, Windows Hello, a security key; first a fresh code, then a tap of its own on *Create now*). Then wherever the code is asked, *With passkey* works too: at sign-in (*Sign in with passkey*) and for important changes (a small window with *With passkey*, *Enter code*, *Cancel*). Safer than the code: the browser signs a one-time challenge of the panel only for this address and only after fingerprint, face or device PIN; another page gets no signature for us. Only over the address with a name (https, e.g. `speech.metaluna9.i234.me`), not over the IP address; each passkey remembers its address. At most 10 per person, removable one by one. The panel keeps only the public key, name, address, when added and last used (in the second step's file; *Set up again* or *Switch off* deletes the passkeys too). Challenges count 2 minutes, once, only for this person, login and address. The app code and recovery codes stay as the way back. In the iPhone app too since V01.0.357 (see the next point). Library: python-fido2 2.2.1 (pinned, with hash in `requirements-panel.lock`, in older environments without dependencies). Change log: `passkey_added`, `passkey_removed`.
- **Passkeys in the iPhone app** (since V01.0.357): wherever the app asks for the code (confirming, Spark update, *Sign in with my profile*, admin sign-in) there is also *With passkey* or *Sign in with passkey*: Face ID signs the same one-time challenge as in the browser. You add the passkey in Safari over the address with a name (*Me → Security* or *Settings → Security*); iCloud Keychain brings it to the app. Adding one in the app is left out on purpose (a new way in stays in the browser). Needed: the app is paired with the address with a name (not the IP address; otherwise it does not show the button), the app has the `webcredentials:` entitlement for that address (build setting `SPARK_PASSKEY_DOMAIN` in `ios/Spark.xcodeproj`), and the Spark serves Apple the file `/.well-known/apple-app-site-association` with the app ID (Team ID and bundle ID from *Features → Push to the iPhone app*; 404 while the iPhone app is off or these are missing). Apple fetches the file over the internet, so the address must be reachable from outside.
- **Chats with other Sparks** (since V01.0.496, off): two addresses are then open without a login, `/.well-known/spark-verbund` (only the public key) and `/api/verbund/in`. There the other Spark's Ed25519 signature over the receiving domain, time (±10 minutes) and a one-time number counts instead of a login; accepted only from paired (or, if the admin wants it, not blocked) Sparks, up to 32 KB, 120 per minute and Spark, and only for people who accepted the request. The answer never reveals whether a person exists. Outbound only to public addresses through the Wächter, not at all during the emergency stop; from outside the emergency stop closes the address from stage 1. Content from other Sparks never goes to the language model.
- **When does the Spark ask for the code?** (since V01.0.427, plan `plaene/zweiter-faktor-einheitlich.md`): three fixed levels from one list in the code (`app/panel/stufen.py`): **Free** (reading, normal settings), **🔒 Confirm** (new accounts, devices, keys, changing people; the code then counts 10 minutes in this login) and **🔒🔒 Change protection** (password, second step, passkeys, roles, restoring and moving backups, kill switch off, Spark update, code words, choosing the main admin; fresh every time). Admins are asked only at this level. A self-test fails when an endpoint with a code is missing from the list or differs from its level. The dialog says whose code, what for and for how long (in the browser and in the iPhone app; the app tries without a code first). Buttons that ask carry 🔒 or 🔒🔒. The whole list is under *Me → Security → When does the Spark ask for the code?*. Aligned: *adding an own MCP service* is now Confirm like the other accounts; the speaker code stays at Change protection like the Home Assistant code word. **One code per person:** when the main admin (a profile with the Admin role) has its own second step, the panel password (now **emergency access**) asks for that profile's code too; the emergency access's own second step stays stored unchanged and counts again as soon as the role or the profile's step is gone. While linked, the second step is changed only in the profile (the emergency access gets 409 with a hint). The "Admin" entry in the authenticator app is then only a fallback. **One sign-in:** a profile with an admin role is admin right after signing in with the second step (code, passkey or trusted browser); a sign-in with only a PIN or by handoff never counts. The panel password is only reachable over the address with `#admin`, browser only. **Locked out?** (since V01.0.439) On the Spark itself `sudo speech-spark notzugang`: new panel password, the emergency access's second step off and the main admin unlinked, roles stay; only as root, never through the panel (`app/panel/notzugang.py`, runs as the service user).
- **Outside text also counts in the next message**: an answer made from web pages, mails, calendar, contacts, documents or smart home texts (media titles, text sensors) is marked. The next message then starts locked (nothing is switched, saved, proposed or reminded; plain switching commands of yours the panel still carries out itself), older such answers are not sent to the model again and never go into automatic learning. Outside text always reaches the model as "data, not an instruction". At most 4 tools per step and 3 notes per answer; "forget" only with a real word and at most 3 hits. Home Assistant direct actions only for lights, switches, covers, climate, media and similar devices, no scripts, automations or buttons.
- **A "yes" is a plain yes**: only yes words count ("Okay, what's the weather?" is not a yes), and any answer settles all proposals waiting in the conversation. In room mode the voice check belongs to the recording of exactly that "yes"; code words never reach the model or the search there either.
- **Someone else's voice**: a voice recognized at someone else's device gets no personal data (no memory, history, documents, calendar, contacts, lists, reminders). Since V01.0.544 (review `pruefung/kontext-trennung-2026-10-14.md`) not along the way either: the briefing does not read out its reminders and the Spark diary is not offered to it (neither over Telegram without "Personal data over Telegram"). A smart home sentence the panel carries out itself is logged only with its word count ("homeassistant: panel ran a command of 7 words -> ok"), never with its text.
- **Outside text switches nothing**: once the assistant read web pages, calendar, documents or earlier conversations in an answer, nothing in that answer can switch Home Assistant, change memory or cancel reminders; after an e-mail it also cannot look anything up on the internet (web search, Wikipedia, weather, transit; since V01.0.916, so no search word carries mail content out) or enter appointments. The panel only runs tools it offered the model in that step. The language model's own markers (`<|im_start|>`, `<tool_call>`) are defused by the Spark in outside text and by the LLM-Tor in every message, so a page cannot fake a new role or a tool call; a smart home state made of words counts as outside, however short.
- **Attack self-test** (since V01.0.916, thread "NeMo Guardrails prüfen"): `app/tests/test_angriffe.py` attacks every way outside text comes in (documents, earlier conversations, calendar, briefing, reading, searching and listing mail, web search, lists with a write link, smart home states and lists, attachments, the answer before) with the collection `app/panel/angriffe.json`: 12 disguises (open, fake system line, faked end of block, tool marker, invisible characters, look-alike letters, HTML comment, alleged confirmation, long text …) and as target every tool that is blocked after outside text. A fake model obeys every order; the test demands that the panel carries out none of it, changes nothing, marks the answer as outside, hands no secret to the model and keeps the data block whole. A new reading tool or one with an effect turns the test red until it is in the collection. It found and closed four gaps: the model's markers in outside text, internet tools after mail, short text states in the smart home, calendar titles in the briefing without a data block.
- **Web search**: the panel reads result pages only from public addresses, never from the home network.
- **Appointments**: a proposed appointment is confirmed only by a plain "yes" in the same conversation.
- **Speaker identification**: the recognition result is given only to signed-in profiles and devices, and it is valid only there. Someone else's voice at a device gets answers but changes no memory.
- **Voiceprint sealed** (since V01.0.517): a profile's voiceprint (`users/<id>/voice.json`) is biometric and lies sealed with the Spark's key (`vault.py`, like passwords), in the backup too. An older open file is sealed the first time it is read (journal "vault: voiceprint sealed"). After a backup restored on another Spark the voiceprint cannot be opened ("vault: voiceprint cannot be opened"); the profile then records its voice anew.
- **Speakers in a room are shared** (since V01.0.226, fixed rule without a switch): anyone in the room can talk to an own speaker, so its device key alone does not count as its owner. Personal things (mail, appointments, reminders, memory, history, documents, contacts, messages, parcels, tasks, smart home, agents) are given there only when speaker identification clearly recognizes the owner's voice in that very recording (Features → speaker identification on, voice taught in the browser or with "teach voice here" at the speaker). Any other or unknown voice gets what a guest gets, and the assistant briefly says it tells that only to the owner; earlier answers at that speaker are not sent along then. Without speaker identification or a taught voice nobody gets personal things at a speaker. Whose voice it was is set only by the panel itself (`esp32.py` → `chat_turn.shared_stranger`), never by a request. Each question kept from personal things this way shows under *State → Logs* in the speakers area as a yellow line "personal data withheld at <speaker> - <reason>" (reason: speaker identification off, no voice taught, voice not recognized, another profile's voice); a recognized owner voice as "owner's voice recognized". Since V01.0.235 numbers come with it: "match 0.68 of 0.75 needed" (similarity with the owner's voice and the value needed, strictness under Me → Speaker identification), "other profiles" (best similarity of another profile), seconds of speech without pauses and "taught here" (sentences taught at the speaker). With less than a second of speech the assistant asks to repeat the question as a whole sentence. "Teach voice here" takes five sentences and reports success only from three well understood ones. The lines name only the speaker and the reason, never the question, voiceprints or content; the speaker's diagnosis (Me → Speakers → Check) shows the same.
- **Code word at a speaker** (since V01.0.297, Features → Speaker recognition → Code word at a speaker, off; released for every profile): three levels (`spkcode.py`). A clearly recognised owner voice as above. **Grey zone** (similarity at most 0.10 below the strictness, the owner still the best match) or an unusual moment (another profile less than 0.05 behind, under 1.5 s of speech, an unknown voice in this speaker's room mode in the last 2 minutes, a wrong code word lately): if the question asks for personal things (fixed word groups like mail, calendar, reminder, smart home or "mein/meine"), the speaker says "Sag bitte dein Codewort." and the question waits 60 s. If the voice was sure and only the moment unusual (a short question, say) and nothing personal is asked, the speaker answers the owner as without the code word: the code word only adds a question before personal things and never takes anything from the sure owner voice (since V01.0.572; before, every short question came as a guest). Right: it is answered with the profile's data, follow-ups stay open for 2 minutes while the voice is at least in the grey zone. Wrong: "Das Codewort stimmt nicht.", nothing personal. After 3 wrong ones in 15 minutes this speaker stops asking for 30 minutes and the profile gets a notification. A **foreign voice** is never asked, so an overheard code word is of no use to it. The code word is an own one (not the smart home code word), at least 2 words and 8 letters, set only in the own browser with a fresh code, sealed in the vault, never sent back. The sentence with the code word goes to no model, history, protocol, diagnosis, board display ("[Codewort]") or journal; the journal only has "code word asked … (reason, numbers)", "right", "wrong (n of 3)", "locked". Waiting questions, failures and locks live in memory only.
- **No changes from foreign pages**: changing requests with a login cookie must come from the panel's own page (`Sec-Fetch-Site`/`Origin`). Scripts with a device key or HTTP Basic are not affected.
- **Secrets encrypted**: calendar and mail passwords and Home Assistant tokens are stored encrypted in the profile folders; the key is kept apart in `/var/lib/speech-spark/state/secret.key`.
- **Devices**: *Profiles* and *Me → Security* show when and from where each device key was last used; one click blocks it.
- **Change log**: *Status → Logs → Changes* lists logins, wrong attempts, lockouts and every change with time, address and who (`/var/lib/speech-spark/state/audit.log`).
  - **Tamper-evident** (since V01.0.780): every line carries the SHA-256 of the line before it, also across files. A line changed, removed or inserted afterwards breaks the chain right there. At 1 MB the file moves to `audit.log.1`, `.2` …; one year is kept (at most 60 files).
  - **Checked daily**: once a day (and after every start) the panel checks the chain and writes `audit: chain ok | … | head …` to the journal, an anchor outside the file. When the chain breaks, the admin pages show a hint that jumps to *Status → Logs → Changes*.
  - **Copy on the NAS**: with the *backup to the outside* on (*Settings → Backup*), every daily backup takes a sealed copy of the whole log along (`speech-spark-protokoll-….log.enc`, AES-256-GCM with the backup password, the newest 7 stay).
  - **Check the log**: the button under *Status → Logs → Changes* (main admin only) checks the chain and compares the newest NAS copy with the log on the Spark: every line of the copy that the Spark still keeps must stand there unchanged. So removing lines on the Spark and recomputing the chain shows too.
- **Sentry** (since V01.0.789, `chat.wachposten` under Features → Sentry, off; `wachposten.py`): fixed rules on the change log tell the admin profiles by notification (tag `wache`) what happens at the doors, never a model. Rules: *lockout* (a lockout after wrong sign-ins starts), *new way in* (trusted browser, passkey, program over MCP, paired Spark, used invitation, iPhone with review code, device for private chats), *protection changed* (admin password, second step off or reset, trusted browsers forgotten, roles, main admin, Notaus key, security setting, GitHub or report token, emergency access, backup restored or downloaded, backup to the outside set up), *change log changed* (chain breaks) and *quality test worse* (questions newly broken after a run, once per run). The notification names only the change log's fixed words (`guard.LIVE_WORDS`) with times, never names, addresses or details, and the way *Status → Logs → Changes*. What comes together within a minute is one notification (at most 6 lines, the rest counted), at most 12 a day, the rest the next day. That cap holds only for lockouts and the quality test: *new way in*, *protection changed* and *change log changed* always go out in the next round and are never dropped from a full queue (V01.0.825, code check 19.10.: about 12 lockouts from the internet would have used up the day and a new passkey would have stayed silent until midnight). Without a reachable device the notification waits. Day and night alike. Counting only while the switch is on. The self-Notaus (*Settings → Security*) stays apart: it closes the doors on a flood, the sentry already reports single events. *Settings → At a glance* shows the sentry and the hash chain under Security. Logs `wachposten: gemeldet | N Einträge | N Admin(s)`, `wachposten: keine Admins mit Gerät | wartet`, `wachposten: Tageshöchstzahl erreicht | …`; Live event "Sicherheit | Wachposten-Hinweis an …". `state/wachposten.json` keeps the queue and times.
- **Trace requests** (since V01.0.262, switch under *Settings → Operation → Logs*, off): *Status → Logs → Requests* lists every request to the assistant (time, profile, device, intent, a bead chain with one dot per step and the tool names, time to the first sound; red on errors, yellow from 5 s to the first sound) and shows the way of the chosen one: "Where the time went" (panel, language model, tools, speech output) on top, below a time line with arrival (device, length of the question), panel preparation (rights, allowed tools, lock after outside text), the switch (intent, tools x of y, required tool), every round of the language model (tokens read, tools offered, which one it calls), every tool (ok or not, characters, whether outside text), the answer check, the speech output (pieces, stalls) and the marks first word, first sound and done. Filters All/Errors/Slow, time range, search, "Related log lines" (journal lines from exactly that time) and "Copy for thread". Only fixed words and numbers are kept, never the question, the answer, tool arguments or results (a tool name the model makes up becomes "unbekannt"); at most 48 hours and 500 requests in `state/traces.jsonl`, not in backups. Per request the panel writes a journal line `anfrage: <id> | device | intent | tools | first sound | done | state` without a name (log area "Request"). The list shows a profile's name and device only when that profile allows it under *Me → Conversation → Privacy → "My name in the request log"* (only in its own browser login, never with a device key; also applies to older entries), otherwise "Profile"; guests and an unknown voice at a speaker show as "Gast"; what the Spark starts itself without a profile (the update check at GitHub every few minutes, backup, rules) shows as "Spark" since V01.0.368. Guests see neither the list nor the live page. The panel password and admins can read it, not the Verwalter role. Since V01.0.462 the errors of a request show as a plain sentence in the red box, with the code (such as `tts_http_400`, `tts_voice`, `llm_down`) small beside it. A piece of the answer with nothing to say (only "---", an emoji, a link, "Haha!") is no longer sent to the speech output at all; if the speech output still refuses a piece as empty, only that piece is skipped and the rest of the answer is spoken (speech output line: "… with nothing to say skipped"). Before, this stopped the whole rest of the speech output with `tts_http_400`. **Thumbs:** when the person rated the answer with 👍 or 👎 (settings assistant), the thumb shows in the list next to the duration. Two more filters 👍 and 👎 show their count. The detail says "Rated after N s" and the fixed reason, for 👎 with a jump to the case under *Status → Improve*; "Copy for thread" carries "Bewertung 👎 (reason)". Only thumb, fixed reason, seconds and case number are kept, never the note or the question; a changed rating replaces the old one.
- **Live page and live monitor** (since V01.0.312, switches under *Settings → Operation → Logs*, both off): *Status → Live* shows in one picture (design "1 Fluss") what the Spark does right now: devices with a running request on the left (group "Over the internet" for requests through the reverse proxy, sender shortened like 89.204.x.x), arrival, guard and the stages listening, switch, language model, tools, speaking in the middle, the targets by zone (on the Spark, home network, internet) on the right. Below: the way of the chosen request with times and "is here now", the guard's decisions with reason and check steps, the door (who came in from outside or was turned away), what the services give back (kind, size, time only), open channels, numbers and events. The last request stays as "last action" until a new one comes; then it fades in 10 seconds. The ⛶ button on "Where the requests go right now" shows only this picture, filling the screen (since V01.0.318; Esc or the button again goes back). While the kill switch is on, a red band shows on top and the picture marks the cut-off targets red and dashed with a lock (since V01.0.325). Everything stays in memory (with "Trace requests" off nothing is written) and is gone after a restart; only fixed words, tool names and numbers, never question, answer, search terms or results; allowed pages from search results show as "Webseite", blocked addresses with address and port. Names only with the profile's consent ("My name in the request log"). The panel password and admins can read it, not the Verwalter role. **Live monitor in the home network** (sub switch): a screen opens `https://<Spark>:31443/live` and enters a 6-digit code once (*New monitor*, valid 10 minutes, once; wrong codes lock like a wrong login). It then keeps a key as a cookie (HttpOnly, SameSite=strict, only as a hash in `state/live-monitors.json`) that may only read `/api/live/state`; unused for 90 days → pair again, *Delete* ends it at once. Requests from the internet are refused (403). At most *At most at once* monitors (1–5, default 3); the monitor shows names only when *Names on the monitor* is on too, else "Person". Codes and pairings go to the admin log. **Using it** (since V01.0.411): *Events* have a chip per area, a search and *Pause* (counting what came in meanwhile); a click on a line lights its place in the picture (Wächter, entrance, GitHub, Begleiter or the request itself) and can open it in *Logs → Requests*. A click on a box in the picture opens a sheet with its state, steps, mean time and failures of the last hour and the last ten as dots; a ⚠ there comes with one sentence what it means and a button to the page that helps. *Rewind* plays the finished requests of the last 15 minutes again (slider or time-lapse; from memory only, nothing new stored, admin page only). Under *Way of the request* are *Copy for thread* and *Open in Logs → Requests*. The *Entrance* card shows how close each self emergency stop rule is to its threshold (e.g. 12/20 wrong sign-ins in 10 minutes). Spark-Begleiter jobs (screen, file, read aloud, meeting, smart home button, reminder, day start, dictation) run as their own way through the picture, the instant acknowledgement shows as "⚡ instant sentence after … s". On the monitor a tap on the turning cards holds the one shown, a second tap lets them turn again. **Colours** (since V01.0.425): amber belongs to the internet alone: the way of a request out of the house (tools → Wächter → target) and the lines to internet targets are amber, each request has another colour, and no two requests in the picture share one. The internet is a lightly amber area ("Over the internet" on the left, the internet targets on the right), set apart from the home targets by a gap. The Wächter stands in it as a dashed wall every connection out passes; what it just blocked ends at the wall for 10 seconds as a red line with ✕, address and reason. Only what is in use has a box of its own (since V01.0.689, Dominik 2026-10-16): a target stays on its own while something runs there, it has a ⚠, it is on the chosen way or it was used in the last 15 minutes (then with "4 min ago"); the language model always stays. The other home and Spark targets share "+ 15 ready", the quiet internet targets "+ 6 quiet"; a tap opens the group, "fold" closes it again (under the kill switch all show singly with their lock). The control centre on the screen folds the same way. A small key to the colours sits on top. ### Data on the disk and new ways to write

- **Find: search index** (since V01.1.245, switch "Find in all data", off): `users/<id>/fund.db` per profile (file 0600, folder 0700) holds only titles, fields, excerpts of the document card and tags, never a document's body. Tags carry an HMAC mark with a key per profile (HKDF from the vault key and the profile id, `vorrat.marke`); a profile searches only its own file with its own marks. The panel sets fields and categories by fixed rules, never the model; the tool's filters count only when the person's own words hold them. "Delete the index" (Find → Settings) and "Delete data" empty the file even while Find is blocked.
- **Find: mail and attachments** (since V01.1.256, switch "Find mail and attachments", off): every mail of the inbox, archive and sent folder (never spam, trash, drafts) with the text of its attachments in `fund.db`, only sealed: subject, excerpt, fields, tag values and own tags AES-GCM (`vorrat.seal`, bound to profile, source, entry and field), words only as HMAC marks; in plain text only source, entry key (mailbox id, folder mark, UID) and date (remaining risk: number and dates of the mails, frequency of equal marks). Without a key nothing is written; below 2048 MB of free space reading stops. Only reading (EXAMINE, PEEK) and only to the own mailboxes; a removed mailbox leaves the search at once. No new way in, no new way of writing out.
- **Find: appointments, contacts, conversations, lists, media** (since V01.1.257, switches "Find appointments", "Find contacts", "Find conversations", "Find lists and reminders", "Find pictures and songs", all off): appointments (only from the copy of the own calendars on the Spark, no fetch of its own, no calendars shared by others) and contacts (name, company, position, town; never numbers, mail addresses, streets) lie in `fund.db` only sealed like mail, their state only as a mark. Of conversations the index holds only date, channel and number of questions; their words are searched by `recall.liste` in the history (answers from mail stay out). Lists and reminders, pictures and songs lie clear like their source; lists of others only while Share lists is on for both and the share is there. Periods (`frisch.spanne`) and "from the surgery" (`fund.bezug_aus`, only from the own words, the appointment only from the own calendars) are fixed rules, never the model; the window around the appointment is a rank bonus, no limit. No new way in or out.
- **Find: tags by the model and Sofort-Karte** (since V01.1.258, switch "Tags by the model", off): the language model in the home network gets the title and excerpt of one entry in quiet minutes (at most 1500 characters, wrapped as data), its answer is only data: a fixed JSON form, a category only from the fixed list, names only word for word from the entry, never a command word, at most 3 to 5 per kind; what the person removed never comes back. For sealed entries (mail, appointment, contact) the model's tags lie sealed with a mark too. People, companies and places only point to points of the knowledge map (read only). The Sofort-Karte says a fixed sentence of the panel with the hit's values (without markup and link signs), never the model's words; the Telegram button `#fund=<no>` is only navigation and opens only what the server shows the profile.
- **Find: measurement, iPhone, companion** (since V01.1.267, no new switch): `sudo speech-spark finden messen` runs as the panel's user in a unit of its own (nice 10, IO idle, `MemoryMax=2G`, `PrivateTmp`), with whole numbers only as values, in a folder of its own beside `users/` (0700, deleted afterwards, also after an error) with made-up data; it touches no profile, only reads the vault key and never makes one (without a key `fund: messung abgelehnt | kein schluessel`). The result only as numbers (journal, `state/fundmessung.json` 0600, Live). The mark store `fund._marke` lives in memory only, per profile and bound to the key, at most 50,000. No new way in or out. The companion (Windows and Mac) opens besides the pages of `chat.DESK_GOTO` only exactly `#fund=` with at most 12 digits; the iPhone uses only paths of `iphone.THINGS["fund"]` and keeps nothing of the index on the device.
- **Supplies sealed** (since V01.0.872/879): what a service read for a profile lies sealed (vault) in the profile as a supply, so answers come with "as of …" during an outage: mail supply (`mail-vorrat.bin`, headers and up to 40 mail texts without attachments), weather, parcel and for-you supply. Not in the backup, "Delete data" removes them. All files: [Architecture → data storage](architecture.md).
- **Unclear questions, anonymous** (since V01.0.927, switch "Keep unclear questions anonymously" under Features → Targeted tool choice, off; preference per profile under Me → Conversation → Privacy): questions no rule of the switch recognizes are kept only redacted (fixed rules as in "Report a problem", plus address book names and every number, a second leak check drops) and sealed in `state/weiche-unklar.json`: without profile, device and time of day, at most 100, gone after 7 days, not in the backup. Never a sentence with the code word, never guests. Only admin and co-admin see and delete them on Features → Routing.
- **Edit contacts** (since V01.0.888, switch "Edit contacts", off): changes go only into the profile's own address book and only with `If-Match` (ETag); when the card changed meanwhile, the Spark overwrites nothing. New cards go into the chosen book or "On the Spark".
- **Search at the mail server** (since V01.0.887): what you type into the search field becomes IMAP `SEARCH` words; only letters, digits, `@`, `.` and `-` get in, never a quote, a word beyond ASCII as a UTF-8 literal. Only the own mailboxes are searched.
- **Hero book to the reMarkable** (since V01.1.143, switch under Features → AI Dungeon Master, off): A hero's book leaves the Spark only on the reMarkable's way (its cloud, `remarkable.place`, daily limits). It holds only the panel's data: catalog, hero values, the own chronicle of fixed kinds and numbers, of people only what was unlocked, of fellow heroes only name, people and class; never a text of the model. Pictures are opened again with Pillow under a pixel and byte bound. State `users/<id>/dungeon-buch.json`, "Delete data" removes it.
- **Remembered note** (since V01.1.249, switch Features → Remembered note, on by default): a conversation keeps per answer only the number and state of the entries remembered (`mem`), never their text; the card "Remembered by itself" lies with the entries' text in the profile's `vorgaenge.json` (7 days). The new way to write `POST /api/profile/memory/{id}/undo` takes back only an own entry and only while it is unchanged since it was remembered; notifications and Telegram get only the number.
- **Memory and conversations sealed** (since V01.1.251, plan *nutzerwissen*, stage 4, no switch: a fixed protection rule like the supply): `memory.json`, `convos.json`, `toollog.json` and `room-history.json` of every profile, since V01.1.252 also what the Spark learned about the person (`learned.json`, `zuordnungen.json`, `memory-ask.json`, `interessen.json`, `tagebuch.json`), lie sealed whole (AES-256-GCM, a key of its own for the purpose "profildaten" from `secret.key` through HKDF, the profile and the file name as associated data, a fresh nonce on every write); which files is said by `siegel=` in the file register. The Spark seals older open files once at the start, after a backup "vor-siegel", and opens each one again as a check. On this Spark every backup opens them again; on another Spark only with the move backup (it carries `secret.key`). Without it the Spark sets the file aside as `<name>.unlesbar`, never overwrites anything, the profile starts empty, and the admins see a hint with its way (Settings → Backup); after the move backup "Read in again" under Me → Memory brings it back. The "Copy of my data" takes them opened into its own encryption and so is the way to rescue them. New way to write `POST /api/profile/memory/einlesen` (only the own profile, rate limit, 256 bytes).
- **People, companies and deadlines in the knowledge map** (since V01.1.253, switch under Features → Own documents → Knowledge book → Knowledge map, off): names of people, companies, places, contracts, accounts (IBAN or number) and deadlines from the own documents lie as the tables `wk_ent` and `wk_ment` in the profile's `wissen.db`, nowhere else, never in the log or in Live (there only a number per kind). Other parts only read them (`wissenskarte.finde_knoten`, `knoten_liste`, a read-only connection). Renaming, merging and deleting happen only by the person's click with the code of "Confirm" (`stufen.LIST`); when a document goes, its passages go with it at once. Since V01.1.273 a fixed rule links a page and a point of the same name (`wk_entpage`, never the model), fixed type rules (`wissenskarte.TYPEN`) hold for every connection, and "Rename page" (`POST /api/profile/wissensbuch/{id}/name`) needs the code of "Confirm" like renaming a point.
- **Measure knowledge** (since V01.1.270, no switch: an admin tool under Status → Checks like "Measure performance", code of the level "Confirm", `app/panel/wissensmessung.py`): a run only reads one profile's `wissen.db` (`PRAGMA query_only` in its own measuring process) or builds a throwaway profile of made-up documents under `state/wissensmessung-tmp/lauf-…` that is deleted afterwards. Only numbers of the last 10 runs are kept in `state/wissensmessung.json` (not in the backup); log and Live show only numbers and fixed words. Endpoints `GET`/`POST /api/admin/wissensmessung` (admins only, rate limits `pruef` and `wmessen`, 512 bytes, one at a time, at most every 5 minutes).
- **Download all my data** (since V01.1.255, plan *nutzerwissen*, stage 5, no switch: right of access, exception in guideline part 3, `app/panel/meinedaten.py`): under Me → Security → My data the Spark packs, after a fresh code or passkey (without a second step after the PIN), everything that belongs to the own profile into a ZIP with `LIESMICH.txt` (de+en) and `uebersicht.json`. What goes in is said only by `export=` in the file register; `profiles.read_own` opens sealed files, sealed values in open files are dropped, databases come as a copy through the SQLite backup, the search index of Find (`fund.db`) readable through `fund.export` (titles, fields, tags and the own ones, never the marks), links are never followed. Staying out with a reason: login and keys (password, passkeys, phone key), the voiceprint, queues, read mails and the supplies of foreign servers; from chats between profiles only the own messages (media only as their kind, private chats not at all). At most 3 per hour and 2 GB (above that 413 with the sizes per area, areas can be left out), packing runs in the background only when it is quiet. The ZIP lies with permissions 600 in the state folder (`export-tmp`) and leaves exactly once through a pickup code (128 bits, only the hash kept, 10 minutes, only the own profile, `Cache-Control: no-store`, in the access log without the code) and is deleted afterwards; a restart empties the folder. The log has `meinedaten: export …` with only a count, MB and milliseconds, Live only how many were packed, picked up, refused or expired. New ways `GET/POST /api/profile/export` and `GET /api/profile/export/{code}`.

## Securing the repository and releases

Since V01.0.390. The GitHub workflows pin every action to a commit (Dependabot proposes updates monthly), only the job that writes a release or build branch may write, and `actions/checkout` keeps no token. The signing keys (Android keystore, App Store Connect key, Developer ID) live in the environment `release`, usable only by workflows on `main`; workflows on other branches cannot see them. The self-test `test_workflows` keeps it that way.

One-time move of the keys: create a fine-grained token for this repository only (Administration, Environments, Secrets: read and write, valid 1 day), store it as repository secret `MIGRATE_TOKEN` and run the workflow "Schlüssel in Umgebung verschieben". It creates `release` (main only, no review), copies every key that is set, then deletes the repository copies and `MIGRATE_TOKEN`. Values never appear in the log.

Recommended on GitHub: 2FA with a passkey, a ruleset on `main` against deletion and force push, read-only workflow permissions, secret scanning with push protection. tars still installs only commits whose tests passed and refuses rewritten history.

### Device updates and supply chain (since V01.0.407)

- **Releases only from the environment `release`**: the jobs that publish the speaker firmware and the Windows companion run in the environment `release` (main only) too; new firmware rolls out to every speaker at night. The ESP-IDF image is pinned to its digest, `pebble-tool` and Playwright to a fixed version; the Pebble SDK itself still comes as "latest" (its list could not be reached when this version was built). The token for the branch `pebble-build` goes through an environment variable, never into the Git URL.
- **Signed manifests (prepared, off)**: the workflows sign `manifest.json` (firmware) and `begleiter.json` (Windows, Mac) with Ed25519 once the secret `UPDATE_SIGNING_KEY` exists in the environment `release`, and put `<file>.sig` into the release. The Spark checks the signature once a public key is listed in `app/panel/signatur.py`; then it takes nothing unsigned. Without a key nothing changes: GitHub over https plus SHA-256 and size from the manifest. Setting it up: `openssl genpkey -algorithm ed25519 -out update-key.pem`, store the content as secret `UPDATE_SIGNING_KEY` under *GitHub → Settings → Environments → release*, run a build and put the public key shown in its log into `signatur.KEYS` (only once all three releases carry a `.sig`). Keep `update-key.pem` offline afterwards.
- **Speaker updates over https**: over http someone in the home network could hand the board a foreign firmware. With *Settings → Security → Lautsprecher-Updates auch über http* switched off (on by default so existing speakers keep updating; changing it needs a code), a speaker that reaches the Spark over http gets no update over Wi-Fi (diagnosis: "nicht über http angeboten"), and the night round skips it; updating over USB in the browser always works. A known board id from another board (different MAC) gets nothing, the key after the code goes only to the address that showed the code, and a wrong `challenge` at activation is refused.
- **Companion**: the Windows and Mac companions load updates only over https. A Mac companion signed with a Developer ID takes only an update from the same team (`codesign -R` with the Team ID from its own signature); an ad-hoc signed one checks size, SHA-256, bundle id and a valid signature as before.
- **iPhone app**: a pairing link to another Spark asks explicitly "Switch to another Spark?" with both addresses; unsent messages do not go along when switching.
- **root and units**: `install.sh` and `update.sh` read `config.json`, the update progress, the engine signatures and `update-target` only as the service user (`as_svc cat`). The API watchdog (`speech-spark-watch`) has `MemoryMax=1G` and `PrivateTmp=yes`; the vLLM engines deliberately have no `MemoryMax` (shared GPU memory).
- **Speech services without an API key**: with an empty `api.key`, ASR and TTS answer only the Spark itself. An old configuration that listens in the network without a key gets a new one at the update.
- **ffmpeg and speech recognition**: every ffmpeg call reads only files and pipes (`-protocol_whitelist file,pipe`); a playlist fetches nothing from the network. The ASR service waits at its gate before it reads a recording (up to 200 MB) into memory; Parakeet decodes one recording at a time, with two threads and a time limit.
- **Telegram voice messages** are downloaded like photos: streamed, cut off after 5 MB, the file path from Telegram checked.
- **Spark update**: if `/etc/speech-spark-signers` exists but is not a plain file of root (a link, another owner, writable by others), the update stops instead of quietly skipping the check. Without the file the update log says "Signature check off". To switch it on: sign commits with an SSH key (`git config gpg.format ssh`, `user.signingkey`, `commit.gpgsign true`) and create `/etc/speech-spark-signers` (root, 644) on the Spark with `<e-mail> <public key>`; from then on tars installs only signed commits.

## Kill switch (Notaus)

The red "Notaus" button (bottom of the sidebar, on phones at the top of Manage) stops the Spark in three stages. Triggering needs no code and only goes up; lifting is for admins only.

| Stage | Name | What stops |
|---|---|---|
| 1 | Outside closed | Everything over the internet or the reverse proxy (also MCP from outside), Telegram; the Spark itself reaches nothing on the internet (netguard, web search, weather, transit, Wikipedia, parcels, reMarkable, firmware and app downloads). The home network goes on. |
| 2 | Hands off | Plus every action: smart home, mail drafts and tidying, messages and announcements, appointments, lists, new reminders, reMarkable, MCP actions, memory. No "yes" carries anything out, waiting proposals are dropped. Running jobs are held, new ones refused; "on its own", Home Assistant notes (and their live connection), briefings, mail tidying and learning pause. The assistant still answers from what it knows and may read. |
| 3 | All quiet | Plus no conversation, no speech recognition; speakers, Wyoming, room mode and reminders are silent. The panel shows only the Notaus page; login, status, logs and lifting work. |

- **Who triggers:** only admins (panel password, profiles with the role Admin or Manager), also from their iPhone app and on the way (since V01.0.338; before, a switch could allow it for every profile). Ordinary profiles see neither the button nor the band nor the Status card; only in stage 3 or from outside a page "The Spark is stopped right now" without a name or reason. Never guests, MCP or the language model; Telegram, voice, Home Assistant and the Android tile only as described under *Other ways* below (since V01.0.360).
- **Lifting:** only the panel password or a profile with the role Admin, only in a browser (no app key, no HTTP Basic), only in the home network, with a fresh code (without a second step: the panel password again). Choice: back to stage 1 or off; held jobs then run on or are cancelled (default).
- **Home network** means a direct connection from a private network. Through a reverse proxy only what a listed proxy (Settings → Security → Reverse proxy) passes on as a home address counts; a listed proxy without that counts as outside. So list the proxy there.
- **Kept** across restart and update (`state/notaus.json`). A damaged file counts as stage 3, never as off. Way out without the panel: `sudo rm /var/lib/speech-spark/state/notaus.json`.
- **Visible:** red band on every page, a card under Status (kinds and counts since it was triggered, never contents), a push to the admin profiles when triggered and lifted, an entry in the admin log. Status → Live and the live monitor /live show a red band with stage, time, channel and per kind "held" with a count (never the reason or a name) and keep running in stage 3 (reading only; pairing a new monitor waits).
- **ESP32 speakers** (firmware build 6 and later, since V01.0.364): hold the BOOT button for 5 seconds. The firmware then sends the fixed wake word "spark-notaus" (only the button sends it, never speech recognition). Only a speaker of an admin profile triggers the big emergency stop, stage 2, and announces it; otherwise it says "only for an admin's speaker". Never *My kill switch*: a button press does not say who pressed it.
- **Pebble watch** (watch app 1.6.0 and later, since V01.0.364): hold SELECT for 3 seconds until it buzzes long, then let go. The watch sends the fixed sentence "Spark, Notaus" (as above: the big one only for admin profiles). "Spark, Mein Notaus" works by dictation.
- **iPhone app** (since V01.0.370, with the next TestFlight build): emergency stop button behind a question and the Siri shortcut "Spark Notaus"; without an admin role only *My kill switch*, never lifting in the app.
- **Emergency stop by itself** (since V01.0.364, switch under *Settings → Security*, off; changing it needs the admin code): the guard switches on stage 1 "Outside closed" by fixed rules, never higher: 20 wrong sign-ins, PINs, codes or emergency stop keys from outside in 10 minutes; an MCP flood from outside (30 MCP requests turned away by the rate limit in 10 minutes); 15 connections refused by netguard in 10 minutes (such as 169.254.x, home addresses or the Spark's own services, where outside text tries to steer the Spark; refusals by the emergency stop itself do not count). Counted in memory only. Channel "Wächter" in the push, the admin log and Status → Live; lifting as always.

### Other ways to the emergency stop (since V01.0.360)

All of these only switch on, never off; lifting stays in the browser. The panel always decides by fixed rules, never the language model and never text from outside.

- **Telegram:** `/meinnotaus` stops the own profile (like *My kill switch*; afterwards Telegram only answers "Mein Notaus ist an"). `/notaus` (stage 2) or `/notaus 1`–`/notaus 3` only for profiles with an admin role; forwarded messages never count as a command. From stage 1 on Telegram itself rests.
- **Fixed sentence** in the chat, by voice on the phone, in the app or at a speaker that recognised the voice: "Spark, Mein Notaus" for every profile, "Spark, Notaus" (stage 2) or "Spark, Notaus Stufe eins/zwei/drei" only for admin profiles. Only the whole sentence, no question about it ("Was ist der Notaus?" triggers nothing). Never over MCP, never for a voice the speaker does not recognise as the profile.
- **Home Assistant:** *Settings → Security → Emergency stop from outside* creates a key (fresh admin code, at most 5, only the hash in `state/notaus-keys.json`, plain text shown once) with ready text for `configuration.yaml`: `rest_command.spark_notaus` (POST `/api/notaus/ha`, `Authorization: Bearer …`, `{"level": 1–3}`, default 2) and a REST sensor on `/api/notaus` with the stage. Home network only; the key reads nothing, lifts nothing and is no device key. Wrong keys lock like wrong logins, rate limit `notausha`.
- **Android tile** (Android app 1.1.0 and later): add "Notaus" in quick settings. It uses the login of the app's page; admins choose "Ganzer Spark" (stage 2) or "Mein Notaus", everyone else only "Mein Notaus", always behind a question. The tile shows the stage.
- The channel shows in the admin log, the push and on Status → Live (telegram, sprache, ha, android).

### My kill switch (own profile only)

Since V01.0.338 every signed-in profile has its own, weaker kill switch under *Me → Security → My kill switch* (admins have it besides the big one). It stops only this profile; the others notice nothing:

- **Ways in closed:** every other browser login ends (the browser that triggered it stays signed in); the profile's device keys (iPhone and Android app, Siri, watch, speakers, Home Assistant events) only get "locked", as do MCP keys, OAuth access and Telegram.
- **Nothing in its name:** smart home, mail drafts and tidying, messages and announcements, appointments, lists, reMarkable, MCP actions; no "yes" carries anything out; jobs wait in the queue; "on its own", Home Assistant notes and briefings of the profile stay silent.
- **Reading stays** (Dominik's choice 3b): in its own browser the profile still asks and may read mail, calendar, memory and documents.
- **Lifting:** the profile itself, only in the browser (no app key), with its PIN (wrong tries lock like at sign-in) and a fresh code when its second step is on; or an admin under *Status → Profiles' own kill switch* (same rules as the big one). The admin profiles get a push with the name, never a reason.
- **File:** `state/notaus-mine.json`. A damaged file holds every profile, and only an admin lifts that. Status → Live shows only how many profiles, never which.

## Reporting problems

Since V01.0.386. Something does not work? Every profile describes it briefly under Me → Reporting problems and gets a draft; guests never. Admin switch: Features → Access → "Reporting problems", plus the target repository (default `db9979/spark-meldungen`, private). It opens everywhere: "Report a problem" at the bottom of the panel, Status → Logs, Ctrl/⌘ K, Me → Reporting problems, in the Android app (panel), in the iPhone app under Settings, in the Spark companion (Windows: the icon's menu; Mac: settings), by Telegram `/melden text` and by voice (also watch and speakers) with the fixed sentence "Spark, Problem melden: …". Telegram and voice only make a draft; sending always comes after a look at the preview.

**What goes along:** the description, if wanted the own last requests (only ways, tools, times from Logs → Requests), the system state (version, services, memory), from the iPhone app the sound log, and for admins only diagnose log lines of the area (10, 30 or 60 min).

**Anonymizing:** fixed rules on the Spark, no language model. First the log redaction, then secrets (everything in the vault, tokens, passwords) become `[GEHEIM]`, contents in log lines (quotes, subject, question, search, appointment, file name …) `[INHALT]`, addresses `[URL]`, `[MAIL]`, `[IP-LAN]`, `[IP]`, `[HOST]`, places `[ORT]`, phone numbers `[TELEFON]`, long identifiers `[ID]`, profile, device and account names `[PERSON-1]`, `[GERÄT-1]`, `[KONTO-1]` (same number for the same name). Code blocks and `@` cannot trigger anything. Only the anonymized version is stored, 14 days.

**Preview and sending:** the Spark shows title and text exactly as they go out; lines can be unticked. Only what matches the preview is sent (a signature over the text); a leak check blocks sending while a known name, a mail address, an address or a secret is still in it. Three ways: "Send to GitHub" (issue via api.github.com), "Open in the browser" (GitHub with the text filled in, works without a token) and "Keep locally only". Limits: per profile 20 open drafts and 10 new a day, 3 sent per profile and 10 per day, one minute apart. **Who sees other drafts:** every profile only its own; all drafts (with names, view, send, delete) only the admin and the admin role, since V01.0.544 no longer the Verwalter (manager) role (review `pruefung/kontext-trennung-2026-10-14.md`).

**Token:** a fine-grained token for the report repository only with "Issues: Read and write", 90 days. Only the main admin saves it with a fresh code (Features → Reporting problems), sealed in the vault, never shown, never logged; classic `ghp_` tokens are refused. "Check" shows the expiry date and warns when the repository is public; 14 days before expiry a hint shows on Status → Live.

**Admin view:** admins see every report of every profile, for sent ones the state on GitHub (open or done), the number of answers and the answers themselves as plain text with a link; a profile sees only its own. Answers from GitHub never go to the language model.

**Tell the admin through the assistant** (since V01.0.386, sub-switch, off): when a profile sends or keeps a report, the assistant tells the admin profiles (role Admin, the main admin first), in the assistant when the page is open, else as a note. Only profile name, area, way and number, never the text; the reporting profile itself gets nothing. Every admin profile turns it off for itself under Me → Reporting problems; during the Notaus it stays silent.

**Live:** Status → Live shows GitHub (reports) with the number of drafts and of those sent today, never contents.

## Stability

- **https without session tickets** (V01.1.243, `panel.tls_context`): with TLS 1.3 session tickets about one https connection in a hundred to Python 3.11's asyncio loop hung after the handshake: the request never arrived, the page waited, a terminal of the Fernzugang never opened. Measured with uvicorn, TLS and one WebSocket alone: of 800 connections 9 hung with tickets, none without. The panel never resumes a session, so nothing is lost. Without tickets there is also no ticket key in memory that could open recorded connections later. The tests of the Fernzugang ways run with exactly this TLS of the panel.
- **Backups**: every day, before every update, before going back to the previous version and before every restore the panel backs up profiles (memory, conversations, documents, calendars, mail accounts, smart home, speaker ID), cloned voices, settings, the panel password and the shared state of the Spark (the admin's second login step, iPhone push key and devices, Telegram bot, browser push key, ESP32 speakers, agent services, own test questions) to `/var/lib/speech-spark/backups`. Counted separately, the newest seven daily or manual ones and the newest five from before an update, rollback or restore are kept. *Settings → Update and backup → Backup* downloads, restores or deletes each one and restores a downloaded file. A restore checks the settings like the settings page does, caps the size and swaps all parts or none; the current state is backed up first. Passwords and tokens are in the backup encrypted, the key is not: on another Spark they have to be entered again. An admin second login step the Spark cannot read is then not taken over (the current one stays). For a move there is the **move backup**: it also carries the key, encrypted with a password you type (at least 12 characters, scrypt + Fernet). It restores only with the same password; a wrong one changes nothing, and after five wrong ones in an hour the panel waits. The Spark's login keys are in no backup, so after a move everyone signs in again. Whoever has the file and the password can read all stored credentials: keep them apart.
- **Backup to the outside** (since V01.0.286, plan "Bedienung gesamt" D4, off): *Settings → Backup → Sicherung nach außen* (main admin only, changes with the admin code). Once a day a move backup goes over WebDAV into a folder (NAS, Nextcloud, Synology; https only, through netguard, home network allowed), first encrypted as a whole with the backup password (scrypt as for the move backup, AES-256-GCM in 1 MiB pieces, each numbered and the last one marked: cutting, swapping or changing shows when decrypting). The NAS only sees encrypted data. Restore: download the file (`…-offsite.tar.gz.enc`) from the NAS and load it under *Aus Datei wiederherstellen* with the backup password, also on a new Spark; wrong passwords count as for the move backup (5 per hour). Without the password the copy is lost: write it down. WebDAV password and backup password are sealed in the vault (`state/offsite.json`, part of the backup), never in a log; a new address needs the WebDAV password again. The last 7 copies stay there; only what this Spark sent itself is deleted. ## Self-test

Every install and update runs the panel's self-test (`app/tests`) against fake LLM, TTS and Home Assistant servers in a throw-away directory: login and access, that profiles never see each other's memory, documents, conversations, mailboxes or Home Assistant, the chat tools, learning from conversations, calendar and text cleaning. It runs before the new version goes live. In an update a failure stops the update and the old version keeps running; on a first install it is only reported. The result is in the update log. It includes the security checks (`test_hardening.py`, one test per guard) and a scanner (`test_scanner.py`) that refuses new code using `shell=True`, `eval` or the like, a route without a login, an upload read without a size limit, values in `onclick` not escaped for JavaScript, or an assistant tool not sorted as "reads outside text / changes something / own data only". By hand: `cd /opt/speech-spark/app && sudo /opt/speech-spark/venv-panel/bin/python -m unittest discover -s tests -t .`

**Gentle updates** (from V01.0.379): when the update installs exactly the version whose GitHub test run passed, the Spark only runs a smoke test (`tests/test_rauchtest.py`, a few seconds: every module loads with this Spark's packages, the panel starts and answers). Since V01.0.643 a panel computer without models of its own (Spark teilen, e.g. a Raspberry Pi 5) always runs only the smoke test; the whole self-test ran past its 900 s there, and GitHub's "Tests" run the whole one for every version. Otherwise the whole self-test still runs on a first install, with `--newest`, `--to` and when going back to the previous version. Both run with the lowest CPU and disk priority (`nice 19`, `ionice` class 2/7), so an answer being spoken keeps its speed. An update asks apt only when a package is missing, pip only when the package list or the lock file changed (`.pkgs` or `.locked` in the environment), and downloads models only when other ones are chosen (`/opt/speech-spark/.models`). The ASR and TTS services restart only when something they run from changed: their files per `app/restart-map`, their systemd unit, the settings or their Python packages; a service the list does not know always restarts, and the smoke test checks the list against the imports. VoiceDesign, like the engines, restarts only when its settings changed. The panel restarts on every update (about 8 s).

**A red main does not go unnoticed** (V01.0.822): when the newest state on GitHub failed the tests, *Settings → Update* says since when ("Red since Mon 23:44"), and the update line in the Live box says the same. The "Tests" run then opens the issue "main rot" on GitHub with the names of the red tests (GitHub tells the repository's owner), adds every further red run and closes it with the next green one. Tests that pass only the second time go as a comment to the issue "Wackelnde Tests". Before every push `tools/vorpush.py` stops while main is red (only the ROT-FIX passes, with `--rotfix`) and runs every test, not only those of the changed files.

**Install overnight** (Settings → Update, off): a new tested version is installed at night between 3 and 5 am, at most once a night, with a backup first. If somebody is talking with the Spark (within the last two minutes) it waits for the next pause; if GitHub cannot be reached it asks again after 15 minutes. Nothing starts during the kill switch. Turning it on needs the second sign-in step when that is on. The "Install update" button asks once more when a conversation is going on. The live view shows a running update under "Running now" with its step and share, its outcome for an hour, and whether "overnight" is on.

**Hands-on test** (since V01.0.697, admin only, not for managers): *Status → Hands-on test* shows what is new and should still be tried out in daily use, the newest first. The check points are one list in the repository (`app/panel/praxistest.json`: number, version, title, steps, thread); every new feature adds its point with the next number, numbers never change. Per point „Works“, „Problem“ or „Later“; „Problem“ shows the way to *Status → Logs → Diagnosis* to give the excerpt with the number to the thread. Points before V01.0.600 that nobody marked are folded away as „old, probably done“, with one button „All old ones done“. Only the word per number is kept (`praxistest-stand.json`, stays on this device), never a text. „Needs you“ names the open points as a quiet line (never red); the iPhone app shows the page under „Manage Spark“. Logs: `praxistest: klappt|problem|spaeter|offen P123`, `praxistest: alt erledigt N`. The steps are written in German.

## Logs

All speech services log into their own journal (`journalctl --namespace=speech-spark -u 'speech-spark-*'`), capped at 500 MB and 14 days; journald deletes older entries automatically. Adjustable under Settings → Operation, effective after the next update. The panel's constant status polls are not logged at all.

**Without profile names** (since V01.0.443): journal lines name a profile only if it agreed under Me → Conversation → Privacy (the same switch as for Logs → Requests); otherwise they say "Profil" and the end of its id, e.g. "iphone: paired for Profil 3f2a". The admin log still names who changed something.

**Diagnostic filters in the panel** (since V01.0.141): *Status → Logs → Diagnostic filters* replaces `journalctl … | grep -E "room:|esp32:" | tail -30` on the console. Tick `chat:`, web search (`chat: web search`), `homeassistant:`, `room:`, `esp32:`, update and self-test (unit `speech-spark-update`) and errors (error, Fehler, traceback, failed, warn); several ticks mean "or", none shows every line. Time range 10 min to 24 h, 30 to 1000 lines (newest kept); "Copy" takes the output including a header with filter and hit count. Admin only, at most 60 requests per minute. Filtering runs in Python against a fixed list; only numbers from fixed lists reach `journalctl`. Bot tokens, bearer keys, `password=`/`token=`/`key=` values and logins inside URLs are blacked out before display.

**Logs page "overview first"** (since V01.0.212): tabs Diagnosis, Services, Update and Changes. Under Diagnosis tiles show the error count and the three busiest areas with a small history over the time range (tap to filter), below the newest error with a fixed hint (e.g. HTTP 401 from Home Assistant → token expired). Filter buttons with counts: conversation, web search, router, Home Assistant, room, speakers, Telegram, mail and "errors only". Each line shows time, area and message; errors red, warnings yellow (fixed word list in the panel), repeated lines as "×n", pauses from 2 min as a divider. Search runs in the browser over the loaded lines only. "Live" reloads every 10 s (services every 3 s) and pauses while you scroll up or select text. "Copy for thread" takes version, filter and the raw lines in a code block.

**Complete log lines** (since V01.0.493, Dominik: "Why does an announcement from the chat not show up in the log?"): until then an announcement wrote a line only when it was said; when it was refused (switch off, no speaker allowed, hourly limit, Notaus, quiet time) nothing was written anywhere. - Lists, appointments, reminders (new filter): entry added, ticked off or deleted (with count, Notaus or kind of error), handed to the iPhone, appointment saved or not, reminder played on a device, deleted or dropped after more than 6 h.
- Notifications (new filter): every notification with its kind (job, reminder, chat …), devices and ways reached, held by "Do not disturb"; browser push without the outside server's text.
- Computer, own services, documents (new filter): acting on the PC (done, declined, no answer), own MCP service (done, declined, error), document sent or refused.
- Memory: fact saved (with its source) or forgotten (count); mail: confirmed sorting, undo, cleanup or draft done, refused or failed; Telegram: document sent or refused.
- Changes tab: announcement, groups, members, invitations, keys and "who may write to me" are in it now; writing, reading and typing in chats stays out.

**A log for everything, checked by tests** (since V01.0.504, Dominik: "Why is the log so inconsistent? … Always put everything new into the log."):
- What Status → Live shows under Events is in the journal too now, whether Live is on or not: `ereignis: <area> | <text>` (new filter "Events (as in Live)"). So companion, documents, Spark help, writing help, Notaus, service watch, device updates, reMarkable sync, speaker recognition, logins and everything else with a Live line are in the log. What the Spark does by itself with a service (update check, NAS backup, device updates) shows as `ereignis: Von selbst | … ok|nicht ok` while Logs → Requests is off.
- Every line has a filter area. New: reMarkable, Apps, By itself, Improve, System and security, Events; existing areas also take related words now (e.g. conversation also Spark help and writing help, storage also backup). Lines without a fixed word at the start ("memory low", "learned …", "github token", "sealing secrets" …) now start with their area.
- "faelle: melder" now names the detector, its fixed sentence (e.g. "12 Fehler in den letzten 24 Stunden") and the case under Status → Improve.
- Confirmed action through the MCP server: `mcp-server: confirmed action <tool> done|fail|no`.
- Three self-tests turn a new gap red: every line needs a word of `logfilter.AREAS`; every function behind a Notaus gate writes a line or names where its line comes from; every exception of the admin log has a reason (`guard.QUIET_WHY`).

**Logs without contents** (since V01.0.513): old lines that still held text now name only fixed words and numbers. Home Assistant writes the length of the spoken command and the number of device words instead of the command, and only the HTTP code instead of the server's answer (device ids like `light.wohnzimmer` stay, so a wrongly switched device can be found). A note the Spark did not say by itself names its reason and length instead of its text, "hamelden" names the profile via `log_name` instead of the raw id and, for a rule by voice, only the kind of condition. A fourth self-test turns every new log line red that shows what was said or written, a foreign server's answer or a raw profile id.

**Errors with a reason instead of "error"** (since V01.0.505, Dominik: log excerpt): requests "by itself" (update check, offsite backup, device updates) name a fixed reason in their line on *Logs → Requests* instead of a bare `error`: `github_limit` (60 questions per hour), `github_http_401` (GitHub refuses, e.g. the read token), `git_ls_remote` (GitHub not reachable), `keine_gruenen_tests`, `ohne_git`; for the backup `http_401` (user or password of the WebDAV folder wrong), `zertifikat` or the kind of error; for device updates the part that failed (`esp32`, `android`, `xiaozhi`). The lines `update check failed: …`, `esp32: firmware check failed`, `android: app check failed` and `geraeteupdate: XiaoZhi check failed` now also show under "Errors only".
- Device updates reported every check as "not ok" while the Android app was on, even when everything worked (the Android check returns a pair that always counted as an error). Fixed; "no app in the repo yet" is no error.
- Settings assistant: a finding that does not change (e.g. "5 errors in the last 24 hours") is no longer counted up every 30 minutes (`faelle: melder | - | fehler | 9×`); only a changed finding is a new entry.
- Meaning search: `docembed: no vector for the question:` names a fixed reason (`not running`, `not enough free memory`, `model did not start`, `model files changed`, `timeout (model busy or slow)` …) instead of a bare `RuntimeError`. A ride along without waking (search locally first, creating documents) while the model sleeps is no error: the journal then says `docembed: question without meaning search (model asleep …)` and the full text search answers.

**Telegram: one poller only** (since V01.0.214): Telegram hands new messages to one `getUpdates` at a time. Up to V01.0.213 the panel's startup tasks ran twice (the https server ran them again), and the two Telegram pollers kicked each other out every 15 s ("Conflict: terminated by other getUpdates request"). Now the https server starts without its own startup tasks, and a second poller in the same process is not started. If Telegram still reports a conflict, another program uses the same bot token: the Spark then waits 5 s, 30 s, 1, 2, 5 and at most 10 min, logs only the second and every 20th time (without the token) and shows a hint under Status and Features → Telegram to use the token in one place only or get a new one from @BotFather. A single conflict right after a restart is normal (the old poll runs for up to 25 s).

**Weather service briefly down** (since V01.0.214): when Open-Meteo answers the weather note with 5xx or 429 or not at all, the log shows a warning ("retry in 10 min") instead of an error, and the Spark tries again every 10 min within the time window.

**Web requests in the logs** (since V01.0.215): for web server lines ("GET /api/… 200 OK") only the status code makes a line red (500 and up), never words in the address. The panel no longer writes the log page's own requests to the journal at all. Update lines quoting a version text ("Available: 46fb0e8 …", "Update finished: …") get no colour (since V01.0.216). The time may read "+0200", "+02:00" or "Z" (since V01.0.217; before, "+02:00" left every area at 0).
